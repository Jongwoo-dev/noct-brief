# NOCT Brief · 녹 브리프

미국 증시의 장전 흐름, 장후 결과, 주요 이벤트를 하루 두 번 정리하는 AI 브리핑 서비스.

Twice-daily AI-powered US stock market briefings covering pre-market outlooks, post-market recaps, and key events.

미국 증시를 이해하기 위해 여러 자료와 시황 영상을 찾아보는 부담을 줄이는 것을 목표로 합니다. 본인이 실제로 사용하면서 누구나 읽을 수 있는 공개 서비스를 지향합니다.

## 현재 상태

새 대화에서 구현을 이어갈 수 있도록 제품 기획과 기술 설계를 정리했습니다. [개발 전 검토 목록](docs/REVIEW_CHECKLIST.md)에서 현재 결정 상태와 다음 검토 항목을 확인할 수 있습니다. 일별 추이·섹터 비교 중심 차트, 현재 화면안을 기준으로 구현 후 조정하는 방식, 조기 폐장·어닝콜 대기·텔레그램 안내 정책을 정했습니다. 별도의 공개 전 운영 시험 기간은 두지 않고 개발 중 내용·기능을 확인하며 보완합니다. 서버/API로 시작하되 생성 부분을 교체할 수 있게 분리하고, 관리자 인증은 Google 로그인을 사용합니다. 환경은 로컬·운영 두 개로 구성할 계획입니다. 4GB 자체 서버와 Node.js 사용을 확정했고 기존 Next.js·TypeScript 구성을 유지합니다. AWS Lightsail을 우선 후보로 하며 PostgreSQL 자체 설치, DB 백업 하루 1회·14일 보관을 확정했습니다. 서버 전체 스냅샷은 제외하고 DB 외부 백업과 서버 재구성·재배포를 기준으로 복구를 설계합니다. 업데이트·백업 세부 운영안, 공개 데이터 공급원·이용권·비용, 운영 모델과 도메인 등 남은 선택을 검토합니다. 문서 작성은 구현 승인이 아닙니다.

핵심 기획은 초기 구현 범위를 정할 만큼 정리했습니다. 새 대화에서 명시적으로 구현을 지시하면 샘플 데이터로 화면·저장·발행 흐름부터 만들 수 있으며, 실제 데이터 공개에는 공급원·이용권·비용 확인이 필요합니다. 애플리케이션 구현과 배포는 시작하지 않았습니다. 실행·빌드·테스트 명령과 배포 결과는 실제 구현 후 검증하여 추가합니다.

## 구현 인계

같은 프로젝트의 새 대화에서 [AGENTS.md](AGENTS.md)의 순서대로 문서를 읽고 “문서 기준으로 구현 시작해”라고 지시하면 됩니다. 모델 변경은 필수가 아니며 사용자가 선택한 기존 모델·추론 강도를 유지할 수 있습니다. 요구사항·구현 순서·검증 기준은 저장소 문서로 전달하며 이전 대화를 다시 읽을 필요가 없도록 관리합니다.

가역적인 세부안은 공통 규칙에 따라 구현하면서 검증·조정합니다. 실제 데이터 공급원·공개 이용권·비용, 운영 모델과 계정, AWS·도메인·백업 저장소는 해당 연동·배포 전에 확인합니다. 샘플 화면만으로 실제 자동 발행 서비스가 완료됐다고 판단하지 않습니다. 구현 승인이 유료 사용·실제 배포·추가 Git 작업까지 자동으로 허용하는 것은 아닙니다.

## 계획 중인 핵심 기능

- 미국 거래일을 기준으로 시장 전체를 다루는 장전·장후 브리핑 자동 공개
- 시장 움직임의 근거, 주요 실적·어닝콜, 예정 이벤트와 결과별 조건부 영향 설명
- PC와 모바일에서 핵심 요약부터 상세 내용과 출처까지 이어지는 읽기 경험
- 다음 브리핑의 발행 예정 시각과 지연 상태 안내

위 기능은 현재 기획 중이며 구현 완료된 기능이 아닙니다. 상세 범위와 발행 시각은 제품 기획 문서를 기준으로 합니다.

## 클론 후 환경 설정 준비

현재는 기획 단계입니다. 아래는 **설정 파일을 준비하는 방법**이며, 애플리케이션 실행 방법은 구현 후 검증하여 추가합니다.

공개 샘플 [.env.example](.env.example)을 루트의 `.env.local`로 복사하고 **복사한 파일만 수정**합니다. 샘플에는 각 항목의 용도, 필요한 시점, 값 준비 방법이 주석으로 들어 있습니다. 다음 명령은 기존 `.env.local`이 있으면 그대로 보존합니다.

PowerShell:

```powershell
if (-not (Test-Path -LiteralPath '.env.local')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env.local'
}
```

macOS/Linux 셸:

```sh
if [ ! -e .env.local ]; then
    cp .env.example .env.local
fi
```

- 로컬 기본값은 `APP_ENV=local`, `DATA_MODE=sample`, 자동 공개·텔레그램 비활성입니다. 샘플 화면과 실제 연동을 분리하는 설계이며 아직 동작을 구현하지 않았습니다.
- DB 저장·로그인을 연결할 때는 본인의 개발 DB 연결 정보와 Google OAuth 설정·세션 비밀키·관리자 식별자를 준비합니다. 콜백 경로와 최초 관리자 식별자 확인 방법은 인증 구현 후 보완합니다.
- 실제 조사·생성에는 API 키와 선택 모델, 실제 차트에는 공개 이용 조건을 확인한 데이터 공급원이 필요합니다. 예약 실행과 텔레그램은 해당 기능을 사용할 때만 설정합니다.
- 세션 키와 예약 호출 키는 각각 다른 난수로 만듭니다. 샘플에 Node.js 설치 후 사용할 생성 명령이 있습니다. 실제 값은 대화·문서·로그에 복사하지 않습니다.
- 운영에서는 환경 변수 이름을 참고해 호스팅 서비스의 비밀정보 설정에 **운영용 값**을 등록합니다. 로컬 DB·키·OAuth 클라이언트와 분리하고 환경 값을 바꾼 뒤에는 서버 재시작 또는 재배포가 필요합니다.

실제 `.env`·`.env.*`, 키 파일, 루트의 `secrets/`·`credentials/`, 호스팅 로컬 설정은 Git에서 제외하고 `.env.example`은 공개 파일로 남깁니다. 별도로 받은 JSON 자격 증명은 일반 소스 폴더에 두지 않고 이 제외된 보관 위치를 사용합니다. 샘플에 실제 값을 채우면 그대로 공개될 수 있으므로 샘플에는 빈 값·설명만 유지합니다.

`.gitignore`는 이미 추적한 파일이나 소스에 직접 적은 비밀 값을 제거하지 않습니다. 커밋할 때 변경 내용을 확인하고, 유출이 확인되면 해당 키를 폐기·재발급한 뒤 이력 처리 범위를 확인합니다. [Git 제외 규칙](https://git-scm.com/docs/gitignore)

API 키·DB 연결 문자열·OAuth 비밀키는 서버에서만 사용하고 `NEXT_PUBLIC_` 이름을 붙이지 않습니다. 해당 접두사는 브라우저에 포함될 값을 지정하는 방식입니다. [Next.js 환경 변수](https://nextjs.org/docs/app/guides/environment-variables), [Better Auth 설정](https://better-auth.com/docs/installation)
