홈은 가장 최신인 공개 보고서 하나를 단독 메인으로 보여줍니다. 세션·거래일, 큰 제목, 짧은 요약 한 문단과 읽기 버튼에 집중하고, 나머지 회차는 아래의 참고용 기록 목록에서 찾습니다. 항목별 해석 라벨·출처·자세한 한계·자료 기준은 상세에서 제공하고, 홈에는 가상 데이터·발행 지연·일부 자료 미반영 안내를 유지합니다. 차트도 상세에서 제공합니다. 기록 목록에서는 메인 회차를 제외하고 미국 거래일별 장전→장후로 묶어 한 페이지에 6개 거래일을 표시합니다. 필터는 지난 회차에만 적용하며 메인 보고서를 바꾸지 않습니다. Lucide 아이콘과 N 표식·파비콘, 기존 색상 원칙은 유지하며 화면의 내용은 여전히 가상 데이터입니다.

상단 안내의 간격을 줄이고 가상 샘플의 제목·첫 요약을 업종 등락·물가 발표·기업 투자 계획 등 본문에 있는 구체적인 내용으로 다듬었습니다. 로컬 DB의 기존 샘플은 이전 버전을 보존해 문구를 갱신했으므로 상세에서 수정 이유를 확인할 수 있습니다. 기본 `db:seed`는 이미 저장된 발행본을 덮어쓰지 않습니다.

상세는 핵심 요약을 먼저 읽고 본문으로 이어지도록 다듬었습니다. 넓은 화면은 옆 목차를, 1000px 이하에서는 요약 다음에 접힌 목차를 제공합니다. 자료 기준·발행 시각을 구분하고 문장 끝 `[1]` 각주로 출처에 이동한 뒤 읽던 위치로 돌아올 수 있습니다. 모바일에서도 선형 차트의 전체 추이와 축 글자 크기를 유지하며, 섹터 막대는 중앙 0선에서 상승은 오른쪽·하락은 왼쪽으로 표시합니다. 정확한 값은 펼치는 표로 확인합니다. 사실·해석·한계는 본문 가까이 유지하고, 하단 출처·정정 이력은 제목과 간격의 강조를 낮춰 제공합니다.

## 비공개 리포트 시험

2026-11-26 자료수집 전용 `research:trial`을 구현하고 Sol 6.2/Astra 6 × high/xhigh 네 조합을 각각 한 번 실행했습니다. 세 조합은 완성됐고 Sol xhigh는 출력 한도로 중단됐습니다. 원문 대조에서는 Sol high를 다음 개선의 기본 후보로 추천했으며 운영 채택은 확정하지 않았습니다. 생성·검증과 별도의 수집 모델·추론 설정 및 평가 기준은 [자료수집 비교 시험](docs/RESEARCH_TRIAL.md), 실제 내용·비용·검증 한계는 [기술 설계 8·12절](docs/TECH_SPEC.md)을 따릅니다. 기존 Codex 자료와의 일치율 대신 실제 필요한 정보의 충족·원문 정확성·시점 적합성을 평가했습니다. 정규 수집·발행 연결은 남아 있습니다.

`npm run report:trial -- YYYY-MM-DD post BUNDLE.json`은 선택한 거래일·세션과 근거의 시각·공개 이용 조건을 검사하고 작성 요청의 비용 예약액을 표시합니다. 새 보고서는 `post`를 사용합니다. 과거 `pre`의 읽기·무료 입력 검사는 호환하되 새 유료 생성은 중단합니다. 입력은 기술 설계 4절의 Bundle JSON입니다.

과거 회차도 원래 자료 마감 시각을 적용합니다. 마감 후에 읽은 출처는 인용한 판본이 당시 공개돼 있었음을 확인한 뒤 `sources[].version`에 그 시각과 근거 URL을 넣습니다. 정규 worker의 자동 웹 수집기는 아직 연결하지 않았으며, 보고서 입력 검사는 직접 확인해 준비한 자료에 적용됩니다. 별도 `research:trial`의 조사 출력은 이 발행용 Bundle과 다른 연구용 계약이며 자동 승인하지 않습니다.

장후 비공개 품질 비교에는 `--quality`를 추가합니다. 제품 명세의 장후 작성 기준을 적용합니다. 현재 `quality-v2`는 핵심 선별·설명 연결·반복 축소를 반영한 기사형 프롬프트입니다. 2026-11-24 사용자 승인으로 누락 자료를 보완하고 GPT-6.1 Sol·GPT-6 Astra·GPT-6.2 Sol의 최초 초안과 검증 완료본을 직접 비교했습니다. 실제 검증 상태와 비용은 기술 설계 12절에 기록합니다. Codex 편집본은 여러 차례 수정한 잠정 비교 대상이며 정답으로 입력하지 않습니다. 기존 v1 결과는 보존합니다. `private_only`로 구분한 사실 메모를 시험에 사용할 수 있습니다. `--run`을 함께 지정하면 일반 시험과 구분해 응답을 저장합니다. 같은 회차의 모든 시험 비용은 하나의 회차 한도에 합산합니다. 생성·검증 모델이 같으면 기존 `<거래일>-post-quality-v2-<모델>.json` 이름을 유지하며, 다른 모델 조합은 두 모델을 포함한 별도 키로 저장합니다. 기존 `quality-v2` 작성 지시는 이전 비교 조건으로 보존하며, 새 통합 구성은 아래 `--combined` 시험으로 구분합니다.

실행 시에는 로컬 PostgreSQL을 켜고 `.env.local`에 `OPENAI_API_KEY`, 생성·보정용 `OPENAI_MODEL=gpt-6-astra`, 검증·재검증용 `OPENAI_VERIFICATION_MODEL=gpt-6.2-sol`을 설정합니다. 같은 명령 끝에 `--run`을 붙이면 해당 프로세스에서 작성·별도 근거 검증을 요청합니다. 샘플 앱의 환경 스위치는 바꿀 필요가 없습니다. 비공개 시험 전용 DB `noct_brief_trial_local`에 응답 ID·사용량·처리 시각을 보존합니다. 검증을 통과하면 `.local/trial-reports/<거래일>-<세션>.json`에서 본문과 주장별 판정, 단계별 비용, 동일 사용량의 GPT-6.1 Sol 비교액과 환산 기준 모델을 볼 수 있습니다. 기존 요청은 저장된 모델·입력으로 재개하고 다른 모델 조합은 별도 시험으로 구분합니다. 단계별 실제 모델로 사용량을 정산합니다. 별도 AI 검증은 현재 비공개 시험 경로에 연결돼 있으며 정규 worker의 의미 검증 연결은 품질 완성 뒤 진행합니다.

새 시간 병기 규칙의 무료 사전 검사는 `npm run report:trial -- YYYY-MM-DD post BUNDLE.json --quality --paired-times`로 실행합니다. `--run`을 붙이지 않으면 API를 호출하지 않습니다. `kst-original-v1` 시간 규칙과 별도 시험 키를 사용하며 이전 `quality-v2` 요청을 덮어쓰지 않습니다. 작성·보정·별도 검증 입력에는 코드가 계산한 근거별 시각 쌍을 제공합니다. 본문의 정확한 관측·사건 시각은 구조화된 입력 필드로 확인돼 있어야 하고, 원문 발췌의 시각을 게시 시각으로 대신 채우지 않습니다. 새 시간 규칙의 무료 검증과 실제 API 생성 품질 비교는 구분합니다.

장후 통합 시험은 `npm run report:trial -- YYYY-MM-DD post BUNDLE.json --combined`로 사전 검사합니다. 현재 옵션은 `combined-v2-kst-original-v1`을 사용하며, 자연스러운 한국어 기사 문장·목록형 예정 안내와 품질을 우선하는 분량 기준을 적용합니다. 다음 실제 거래일 폐장까지의 일정, 간결한 시간 병기와 근거 검사는 유지합니다. 이전 `combined-v1`은 `--combined-v1`으로 사전 검사하거나 이미 접수된 응답만 조회할 수 있습니다. 두 옵션은 함께 쓰지 않습니다. 8,000토큰 상한으로 접수된 시험을 재개할 때는 해당 실행에만 `OPENAI_MAX_OUTPUT_TOKENS=8000`을 지정합니다. 새 유료 실행은 별도 승인 범위에서 `--run`을 추가하며, 기존 한 번의 보정·재검증 한도는 유지합니다. 이전 보고서·입력·요청은 보존합니다.

키를 만들 때 해당 OpenAI 프로젝트의 API Keys에서 **Restricted**를 선택합니다. 실행에 쓰는 엔드포인트는 `POST /v1/responses`(모델 요청)와 `GET /v1/responses/{id}`(결과 회수)입니다. Responses의 생성·읽기를 허용하고, 모델 실행 권한을 따로 표시하는 화면에서는 해당 요청을 허용합니다. 비용은 응답의 `usage`로 계산합니다. ### 개발 서버

Node.js 24 LTS와 npm을 사용합니다. 잠금 파일 기준 Next.js 16.4.6, React 19.3.1, TypeScript 7.0.2, Better Auth 1.7.14입니다.

```sh
npm ci
npm run dev
```

[로컬 화면](http://127.0.0.1:3000)을 엽니다. DB 설정이 없으면 네 가지 가상 회차를 읽기 전용으로 표시합니다. 화면에 가상 데이터임을 명시하며 로그인·외부 호출을 우회하지 않습니다.

Windows에서 `listen EACCES`가 발생하면 점유 프로세스뿐 아니라 `netsh interface ipv4 show excludedportrange protocol=tcp`로 예약 범위도 확인합니다. 필요하면 조회 권한이 있는 터미널을 사용합니다. 3000이 예약됐다면 예약·점유되지 않은 다른 포트로 `npm run dev -- --port 3300`처럼 임시 실행할 수 있습니다. 2026-11-26에는 이 방식으로 공개 화면을 검증했습니다. 포트만 바꾸어도 기존 OAuth 원본·콜백이 바뀌는 것은 아니므로 대체 포트에서 관리자 로그인까지 확인한 것으로 취급하지 않습니다.

개발 실행은 Webpack을 사용합니다. 2026-11-01 Windows 로컬에서 기본 Turbopack 실행 중 코드 수정 없이 재컴파일·페이지 갱신이 반복되어, 같은 앱에서 반복이 멈춘 Webpack으로 개발 명령을 전환했습니다. 프로덕션 빌드 설정은 유지합니다. 코드를 저장했을 때의 일회성 갱신은 정상이며, 아무 수정 없이 계속 새로고침되는 것은 정상 동작이 아닙니다.

저장·작업 처리까지 확인하려면 별도 터미널에서 다음을 실행합니다.

```sh
npm run db:local
```

전용 PostgreSQL을 loopback 55432에서 실행합니다. `.local/`에 DB와 임의 비밀번호를 저장하고 `.env.local`의 비어 있는 DB 설정만 채웁니다. 기존 설정은 덮어쓰지 않습니다. 이 터미널을 유지한 채 다른 터미널에서 실행합니다.

```sh
npm run db:migrate
npm run db:seed
npm run dev
```

이미 실행 중인 앱은 환경 파일 변경 후 재시작합니다. 개발 DB 이름은 `_local`로 끝나야 하며 원격 운영 DB를 로컬 앱에서 사용할 수 없습니다. `npm run worker -- --sample`은 로컬 가상 작업을 한 번 처리합니다. 대기 중인 단계는 다음 수동 실행에서 이어지며 외부 API·텔레그램을 호출하지 않습니다.

이 명령은 읽기 전용 상태 조회가 아닙니다. 마지막 예약 실행 이후 최대 31일의 누락 회차를 등록합니다. 발행 예정 시각이 지난 최신 회차 하나만 생성 대상으로 두고 앞선 회차는 미발행 안내로 마감한 뒤, 실행 가능한 작업 단계를 최대 8번 처리합니다. 기존 샘플 DB에 누락 회차를 추가하려는 경우에만 실행하며, 운영 흐름 시험은 분리된 테스트 DB를 우선 사용합니다. 관리자 화면의 「대기 작업 한 단계 진행」은 회차 자동 등록 없이 실행 시각이 된 작업 하나를 처리합니다.

### 관리자 확인

- `/admin`: Google 관리자 로그인 뒤 회차 상태·거래일 필터, 보관된 현재/이전 버전, 작업 이력과 예외 알림을 확인합니다. 실패한 최신 작업만 재시도하며 정정 요청·공개/비공개 조작은 회차 상세에서 수행합니다.
- 로컬에서 `npm run db:seed`를 실행하고 관리자에 로그인하면 비공개 정정 샘플 세 건을 확인할 수 있습니다. 「확인 필요」에는 재시도 가능한 호출 제한과 재시도가 차단된 접수 불명 사례가, 「처리 중」에는 발행 대기 사례가 있습니다. 다시 시드해도 기존 회차와 조작 결과는 보존됩니다.
- 로그인한 로컬 sample 관리자에서는 「더미 리포트로 발행 흐름 테스트」로 회차를 등록하고 대기 작업 하나를 한 단계씩 진행할 수 있습니다. 내용은 가상 자료지만 저장·검증·공개 처리는 실제 로컬 DB를 사용합니다. 같은 회차 중복 등록과 목표 시각 이전 공개는 막으며 외부 API는 호출하지 않습니다.
- [로컬 관리자](http://localhost:3000/admin)에서 실제 Google 로그인·관리자 조회·로그아웃·재로그인과 더미 발행·비공개/복구·정정·실패 재시도를 확인했습니다. 시험 회차는 두 버전을 비공개 보관했고 기존 샘플은 유지했습니다. 수집 실패는 의도한 모의 오류이며 실제 외부 생성 품질 검증과 구분합니다. 상세 범위는 기술 설계 12절을 따릅니다.

### 환경 변수

각 환경 변수의 용도·입력 방법·필수 조건은 [.env.example](.env.example)의 해당 항목 바로 위에 있습니다. 처음 설정할 때는 이 파일을 `.env.local`로 복사해 실제 값을 입력하고, 이미 `.env.local`이 있으면 필요한 항목만 추가합니다. 모든 비밀 값은 서버 전용이며 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. Git 제외는 이미 추적된 비밀 값을 제거하지 않으므로 커밋 전 변경 내용을 확인합니다.

| 설정 | 용도와 필수 조건 |
| --- | --- |
| `APP_ENV`, `DATA_MODE` | 기본 local/sample. 운영은 production/live와 DB·HTTPS URL 필수 |
| `DATABASE_URL` | DB 저장·인증. 로컬 loopback + _local; DB 환경·모드 표식 검사 |
| `BETTER_AUTH_URL` | 기본 localhost:3000, 운영 HTTPS 도메인 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `BETTER_AUTH_SECRET`, `ADMIN_GOOGLE_SUB` | Google 단일 관리자. 세션 키 최소 32자; sub 미설정 시 관리 권한 없음 |
| `EXTERNAL_CALLS_ENABLED`, `OPENAI_API_KEY`, `OPENAI_MODEL` | 외부 호출 활성화·인증과 생성·보정 모델. 선택값은 `gpt-6-astra`입니다. |
| `OPENAI_VERIFICATION_MODEL` | 별도 근거 검증·재검증 모델. 선택값은 `gpt-6.2-sol`이며 미지정 시 생성 모델로 호환합니다. 현재 별도 검증은 비공개 시험에 연결돼 있습니다. |
| `OPENAI_REASONING_EFFORT`, `OPENAI_MAX_OUTPUT_TOKENS` | 기본 medium/10000, 회차별 설정 저장 |
| `OPENAI_RESEARCH_MODEL`, `OPENAI_RESEARCH_REASONING_EFFORT` | 비공개 수집 시험 전용. 기본 Sol 6.2/high이며 생성·검증 설정과 독립. high/xhigh 비교 가능 |
| `OPENAI_RESEARCH_MAX_OUTPUT_TOKENS`, `OPENAI_RESEARCH_MAX_TOOL_CALLS` | 수집 시험의 추론 포함 출력 상한 32000, 내장 도구 전체 실행 상한 40. 최적값 검증 전 |
| `MARKET_DATA_PROVIDER`, `MARKET_DATA_API_KEY` | 공급원 확정 후 연결할 예약 항목; 현재 직접 API 수집기 미연결 |
| `AUTO_PUBLISH_ENABLED` | 운영 Node.js 서버가 시작할 때 발행 작업을 등록합니다. production/live에서 `EXTERNAL_CALLS_ENABLED=true`일 때 활성화할 수 있습니다. |
| `AUTO_BACKUP_ENABLED` | 운영 일일 DB 백업, 26시간 누락 점검, 백업 예외 알림 재시도를 함께 켭니다. 발행 설정과 독립이며 기본값은 `false`입니다. 로컬에서는 자동 발행과 자동 백업을 모두 끕니다. |
| `TELEGRAM_ENABLED`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | 운영 예외 알림만. 로컬 활성화 차단 |
| `BACKUP_BUCKET`, `PG_CLIENT_BIN` | 외부 백업 버킷과 PostgreSQL 클라이언트 경로. AWS CLI 인증 별도 |
| `RESTORE_DATABASE_URL`, `CONFIRM_RESTORE` | 현재 앱 DB와 분리되고 다른 연결이 없는 빈 DB 복원. 확인 값 empty-database |
| `CONFIRM_PRODUCTION_MIGRATION` | 운영 마이그레이션 실행 시 production |
| `TEST_BASE_URL`, `NOCT_DOMAIN` | HTTP 검사 대상과 운영 Caddy 도메인 |

Google 설정 변경은 별도 승인 후 진행합니다. 로컬 전용 프로젝트 `NOCT Brief Local`은 외부 사용자 유형의 테스트 모드로 유지하며 본인 계정만 테스트 사용자로 등록했습니다. 운영 프로젝트·클라이언트는 아직 만들지 않았습니다. 로컬 웹 OAuth 원본은 `http://localhost:3000`, 콜백은 `http://localhost:3000/api/auth/callback/google`, 운영 콜백은 `https://선택도메인/api/auth/callback/google`입니다. 로컬 관리자에 `127.0.0.1`로 접속하면 설정한 `localhost`로 이동해 쿠키·콜백 주소를 일치시킵니다.

처음 연결하는 환경에서는 `ADMIN_GOOGLE_SUB`를 비운 채 본인이 로그인하고 `/admin`에 표시되는 검증된 sub를 비밀 설정에 등록한 뒤 재시작합니다. 현재 로컬은 이 등록을 완료했습니다. 자동으로 첫 사용자를 관리자로 등록하지 않으며 이메일·클라이언트 값으로 권한을 결정하지 않습니다. 로그인 범위는 `openid email profile`, 온라인 접근만 요청하고 Drive/Gmail·오프라인 접근은 요청하지 않습니다. OAuth 액세스·갱신 토큰의 DB 암호화를 사용하므로 `BETTER_AUTH_SECRET`도 환경 파일·DB 백업과 함께 안전하게 관리합니다. 이 설정이 DB 전체나 ID 토큰까지 암호화하는 것은 아닙니다.

## 검사와 빌드

```sh
npm run typecheck
npm test
npm run test:integration
npm run test:http
npm run build
npm run release:package
```

통합 검사는 실행 중인 로컬 DB와 `pg_dump`/`pg_restore`가 필요합니다. 본 테스트가 만든 임의 이름의 분리 DB만 생성·제거합니다. PostgreSQL 클라이언트는 서버와 같은 버전 이상을 준비합니다. Windows 개발에서는 PostgreSQL 18.4와 공식 EDB 18.6 클라이언트로 검증했습니다. HTTP 검사는 실행 중인 앱이 필요합니다. `npm run check`는 정적 검사·단위·DB 통합·빌드를 순서대로 실행합니다.

배포 묶음은 빌드 후 `dist/release-시각/`에 허용된 파일만 복사하고 manifest를 만듭니다. **이 명령은 배포하지 않습니다.** 운영 Linux용 묶음은 Linux에서 다시 설치·빌드·묶음 생성 후 준비해야 합니다. Windows 빌드를 운영 서버에 그대로 복사하지 않습니다. [운영·복구 절차](docs/OPERATIONS.md)를 따릅니다.
