# NOCT Brief · 녹 브리프

미국 증시의 장전 흐름, 장후 결과, 주요 이벤트를 하루 두 번 정리하는 AI 브리핑 서비스.

## 현재 상태

2026-11-18 사용자 결정에 따라 **실제 리포트 생성·자료 수집·AI 검증 연결과 품질 조정은 마지막 단계로 미룹니다.** 관리자 화면과 발행 관리 흐름을 먼저 다듬었습니다. 내용 생성은 기존 더미를 사용하고 상태 조회·저장·재시도·정정·공개 여부는 실제 로컬 로직으로 검증합니다. 생성 관련 결정·구현 상태는 유지하며 현재 우선순위는 기술 설계 10절을 따릅니다.

2026-10-27 구현 지시에 따라 공개 화면, PostgreSQL 저장·버전 관리, 예약 작업·재시도·정정, Google 관리자 인증 경계, AI 생성 어댑터, 텔레그램 예외 알림, 백업·복원·배포 준비 코드를 구현했습니다. 로컬의 네 가지 가상 시황과 실제 PostgreSQL로 검증했습니다.

**실제 시황 자동 서비스는 아직 가동하지 않았습니다.** 시장 데이터의 공개 이용권·공급원, 실제 자료 조사/수집기, 운영 모델과 계정 연결이 남아 있습니다. 현재 live 수집 경계는 검증된 자료 묶음을 DB에서 읽습니다. API 생성기는 연결 코드와 모의 응답 검사까지 완료했으며 유료 요청은 실행하지 않았습니다. 외부 계정 설정은 사용자 승인에 따른 로컬 Google 로그인 연결만 진행했습니다. 운영 자원 구매·배포는 수행하지 않았습니다.

실제 확인한 범위와 미확인 사항은 [기술 설계 12절](docs/TECH_SPEC.md#12-구현-상태와-검증-결과--2026-10-27), 필요한 선택과 추천은 [외부 연동 준비](docs/INTEGRATION_READINESS.md)에 정리합니다.

2026-11-17 공식 출처를 재사용하고 사건별 웹 검색으로 보완하는 수집 방향을 정리했고, 후속 답변에서 사용자가 첫 시험의 회차·하루·누적 비상 금액을 수락했습니다. 금액과 범위는 기술 설계 8절을 따릅니다. 생성 후 첨부 근거와 보고서 내용의 대조 요구도 반영했습니다. 자동 조사·금액별 차단·원문과 문장의 의미 검증은 아직 미구현이며 모델·공급원 계약·계정 설정은 미확정입니다. API의 지출 한도·크레딧 부족 응답을 일시 호출 제한과 구분해 자동 재시도를 중단하도록 보완했고 단위 검사와 빌드를 통과했습니다.

2026-11-18 Next.js를 16.4.3에서 **16.4.6**으로 보안 업데이트했습니다. 전체 의존성의 `npm audit` 검출 항목이 1건에서 0건으로 줄었고, 단위 49개·DB 통합 18개·타입·형식·빌드·독립 실행 묶음의 HTTP 검사를 통과했습니다. 홈·상세·관리자 시연의 브라우저 동작도 확인했습니다. 실제 운영 배포와 Google 로그인 검증은 포함하지 않았으며 자세한 범위는 기술 설계 12절을 따릅니다.

같은 날 승인된 `NOCT Brief Local` 전용 프로젝트와 웹 OAuth 클라이언트를 구성했습니다. 실제 Google 로그인→권한 미등록 상태→본인 sub 등록→관리자 목록·보관본 조회→로그아웃·재로그인을 확인했습니다. 인증 권한·환경 경계 검사 6개를 추가해 단위 55개, DB 통합 18개, OAuth 시작 응답을 포함한 HTTP 검사와 빌드를 통과했습니다. 후속으로 인증된 브라우저에서 더미 회차 등록·발행·비공개/복구·정정·실패 재시도·이전 버전 조회를 확인했습니다. 다른 실제 Google 계정의 로그인 거부는 아직 검증 전입니다.

2026-11-01 실제 다크 사이트를 조사해 홈의 정보 위계·블랙 표면과 상세 읽기 배치를 조정했습니다. 후속 가독성 피드백에 따라 최신 제목·요약을 강조하고 중간 화면 폭부터 한 열로 배치했으며, 행동·주의·데이터의 색상 역할을 분리했습니다. 앞으로 유지할 색상 배분·역할·대비·정보 위계 원칙은 [제품 명세 10절](docs/PRODUCT_SPEC.md#지속-적용할-디자인-원칙--사용자-확정)에 기록했습니다. 같은 절에 참고 화면과 현재 색상·서체 기준을 관리하며, 최종 미감은 사용자 피드백을 반영해 조정 중입니다.

홈은 가장 최신인 공개 보고서 하나를 단독 메인으로 보여줍니다. 세션·거래일, 큰 제목, 짧은 요약 한 문단과 읽기 버튼에 집중하고, 나머지 회차는 아래의 참고용 기록 목록에서 찾습니다. 항목별 해석 라벨·출처·자세한 한계·자료 기준은 상세에서 제공하고, 홈에는 가상 데이터·발행 지연·일부 자료 미반영 안내를 유지합니다. 차트도 상세에서 제공합니다. 기록 목록에서는 메인 회차를 제외하고 미국 거래일별 장전→장후로 묶어 한 페이지에 6개 거래일을 표시합니다. 필터는 지난 회차에만 적용하며 메인 보고서를 바꾸지 않습니다. Lucide 아이콘과 N 표식·파비콘, 기존 색상 원칙은 유지하며 화면의 내용은 여전히 가상 데이터입니다.

상단 안내의 간격을 줄이고 가상 샘플의 제목·첫 요약을 업종 등락·물가 발표·기업 투자 계획 등 본문에 있는 구체적인 내용으로 다듬었습니다. 로컬 DB의 기존 샘플은 이전 버전을 보존해 문구를 갱신했으므로 상세에서 수정 이유를 확인할 수 있습니다. 기본 `db:seed`는 이미 저장된 발행본을 덮어쓰지 않습니다.

상세는 핵심 요약을 먼저 읽고 본문으로 이어지도록 다듬었습니다. 넓은 화면은 옆 목차를, 1000px 이하에서는 요약 다음에 접힌 목차를 제공합니다. 자료 기준·발행 시각을 구분하고 문장 끝 `[1]` 각주로 출처에 이동한 뒤 읽던 위치로 돌아올 수 있습니다. 모바일에서도 선형 차트의 전체 추이와 축 글자 크기를 유지하며, 섹터 막대는 중앙 0선에서 상승은 오른쪽·하락은 왼쪽으로 표시합니다. 정확한 값은 펼치는 표로 확인합니다. 사실·해석·한계는 본문 가까이 유지하고, 하단 출처·정정 이력은 제목과 간격의 강조를 낮춰 제공합니다.

## 로컬 실행

Node.js 24 LTS와 npm을 사용합니다. 잠금 파일 기준 Next.js 16.4.6, React 19.3.1, TypeScript 7.0.2, Better Auth 1.7.14입니다.

```sh
npm ci
npm run dev
```

[로컬 화면](http://127.0.0.1:3000)을 엽니다. DB 설정이 없으면 네 가지 가상 회차를 읽기 전용으로 표시합니다. 화면에 가상 데이터임을 명시하며 로그인·외부 호출을 우회하지 않습니다.

개발 실행은 Webpack을 사용합니다. 2026-11-01 Windows 로컬에서 기본 Turbopack 실행 중 코드 수정 없이 재컴파일·페이지 갱신이 반복되어, 같은 앱에서 반복이 멈춘 Webpack으로 개발 명령을 전환했습니다. 프로덕션 빌드 설정은 유지합니다. 코드를 저장했을 때의 일회성 갱신은 정상이며, 아무 수정 없이 계속 새로고침되는 것은 정상 동작이 아닙니다.

저장·작업 처리까지 확인하려면 별도 터미널에서 다음을 실행합니다.

```sh
npm run db:local
```

전용 PostgreSQL을 loopback 55432에서 실행합니다. `.local/`에 DB와 임의 비밀번호를 저장하고 `.env.local`의 비어 있는 DB 설정만 채웁니다. 기존 설정은 덮어쓰지 않습니다. 이 터미널을 유지한 채 다른 터미널에서 실행합니다.

```sh
npm run db:migrate
npm run db:seed
npm run dev
```

이미 실행 중인 앱은 환경 파일 변경 후 재시작합니다. 개발 DB 이름은 `_local`로 끝나야 하며 원격 운영 DB를 로컬 앱에서 사용할 수 없습니다. `npm run worker -- --sample`은 로컬 가상 작업을 한 번 처리합니다. 대기 중인 단계는 다음 수동 실행에서 이어지며 외부 API·텔레그램을 호출하지 않습니다.

## 설정

### 관리자 확인

- `/admin`: Google 관리자 로그인 뒤 회차 상태·거래일 필터, 보관된 현재/이전 버전, 작업 이력과 예외 알림을 확인합니다. 실패한 최신 작업만 재시도하며 정정 요청·공개/비공개 조작은 회차 상세에서 수행합니다.
- `/admin/preview`: 로컬 sample 모드에서 로그인 없이 고정 가상 자료로 같은 화면을 둘러봅니다. 실제 DB를 읽거나 관리 명령을 실행하지 않으며 저장·실행 버튼은 비활성화됩니다. production 또는 live 모드에서는 제공하지 않습니다.
- 로그인한 로컬 sample 관리자에서는 「더미 리포트로 발행 흐름 테스트」로 회차를 등록하고 대기 작업 하나를 한 단계씩 진행할 수 있습니다. 내용은 가상 자료지만 저장·검증·공개 처리는 실제 로컬 DB를 사용합니다. 같은 회차 중복 등록과 목표 시각 이전 공개는 막으며 외부 API는 호출하지 않습니다.
- [로컬 관리자](http://localhost:3000/admin)에서 실제 Google 로그인·관리자 조회·로그아웃·재로그인과 더미 발행·비공개/복구·정정·실패 재시도를 확인했습니다. 시험 회차는 두 버전을 비공개 보관했고 기존 샘플은 유지했습니다. 수집 실패는 의도한 모의 오류이며 실제 외부 생성 품질 검증과 구분합니다. 상세 범위는 기술 설계 12절을 따릅니다.

### 환경 변수

[.env.example](.env.example)을 기존 `.env.local`이 없을 때만 복사하고 복사한 파일에 값을 넣습니다. 모든 비밀 값은 서버 전용이며 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. Git 제외는 이미 추적된 비밀 값을 제거하지 않으므로 커밋 전 변경 내용을 확인합니다.

| 설정 | 용도와 필수 조건 |
| --- | --- |
| `APP_ENV`, `DATA_MODE` | 기본 local/sample. 운영은 production/live와 DB·HTTPS URL 필수 |
| `DATABASE_URL` | DB 저장·인증. 로컬 loopback + _local; DB 환경·모드 표식 검사 |
| `BETTER_AUTH_URL` | 기본 localhost:3000, 운영 HTTPS 도메인 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `BETTER_AUTH_SECRET`, `ADMIN_GOOGLE_SUB` | Google 단일 관리자. 세션 키 최소 32자; sub 미설정 시 관리 권한 없음 |
| `EXTERNAL_CALLS_ENABLED`, `OPENAI_API_KEY`, `OPENAI_MODEL` | 실제 생성 API를 명시적으로 켤 때 필요. 모델 기본값 없음 |
| `OPENAI_REASONING_EFFORT`, `OPENAI_MAX_OUTPUT_TOKENS` | 기본 medium/8000, 회차별 설정 저장 |
| `MARKET_DATA_PROVIDER`, `MARKET_DATA_API_KEY` | 공급원 확정 후 연결할 예약 항목; 현재 직접 API 수집기 미연결 |
| `AUTO_PUBLISH_ENABLED`, `CRON_SECRET` | 운영 자동 실행 시 외부 호출 활성화와 별도 32자 키 필요 |
| `TELEGRAM_ENABLED`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | 운영 예외 알림만. 로컬 활성화 차단 |
| `BACKUP_BUCKET`, `PG_CLIENT_BIN` | 외부 백업 버킷과 PostgreSQL 클라이언트 경로. AWS CLI 인증 별도 |
| `RESTORE_DATABASE_URL`, `CONFIRM_RESTORE` | 분리된 빈 DB 복원. 확인 값 empty-database |
| `CONFIRM_PRODUCTION_MIGRATION` | 운영 마이그레이션 실행 시 production |
| `TEST_BASE_URL`, `NOCT_DOMAIN` | HTTP 검사 대상과 운영 Caddy 도메인 |

Google 설정 변경은 별도 승인 후 진행합니다. 로컬 전용 프로젝트 `NOCT Brief Local`은 외부 사용자 유형의 테스트 모드로 유지하며 본인 계정만 테스트 사용자로 등록했습니다. 운영 프로젝트·클라이언트는 아직 만들지 않았습니다. 로컬 웹 OAuth 원본은 `http://localhost:3000`, 콜백은 `http://localhost:3000/api/auth/callback/google`, 운영 콜백은 `https://선택도메인/api/auth/callback/google`입니다. 로컬 관리자에 `127.0.0.1`로 접속하면 설정한 `localhost`로 이동해 쿠키·콜백 주소를 일치시킵니다.

처음 연결하는 환경에서는 `ADMIN_GOOGLE_SUB`를 비운 채 본인이 로그인하고 `/admin`에 표시되는 검증된 sub를 비밀 설정에 등록한 뒤 재시작합니다. 현재 로컬은 이 등록을 완료했습니다. 자동으로 첫 사용자를 관리자로 등록하지 않으며 이메일·클라이언트 값으로 권한을 결정하지 않습니다. 로그인 범위는 `openid email profile`, 온라인 접근만 요청하고 Drive/Gmail·오프라인 접근은 요청하지 않습니다. OAuth 액세스·갱신 토큰의 DB 암호화를 사용하므로 `BETTER_AUTH_SECRET`도 환경 파일·DB 백업과 함께 안전하게 관리합니다. 이 설정이 DB 전체나 ID 토큰까지 암호화하는 것은 아닙니다.

## 검사와 빌드

```sh
npm run typecheck
npm test
npm run test:integration
npm run test:http
npm run build
npm run release:package
```

통합 검사는 실행 중인 로컬 DB와 `pg_dump`/`pg_restore`가 필요합니다. 본 테스트가 만든 임의 이름의 분리 DB만 생성·제거합니다. PostgreSQL 클라이언트는 서버와 같은 버전 이상을 준비합니다. Windows 개발에서는 PostgreSQL 18.4와 공식 EDB 18.6 클라이언트로 검증했습니다. HTTP 검사는 실행 중인 앱이 필요합니다. `npm run check`는 정적 검사·단위·DB 통합·빌드를 순서대로 실행합니다.

배포 묶음은 빌드 후 `dist/release-시각/`에 허용된 파일만 복사하고 manifest를 만듭니다. **이 명령은 배포하지 않습니다.** 운영 Linux용 묶음은 Linux에서 다시 설치·빌드·묶음 생성 후 준비해야 합니다. Windows 빌드를 운영 서버에 그대로 복사하지 않습니다. [운영·복구 절차](docs/OPERATIONS.md)를 따릅니다.
