## 2. 브랜드 방향과 기본 테마 — 확정, 세부 디자인은 초기 기준 채택

NOCT는 한국에서 밤에 미국 증시를 살펴보는 경험과 연결되는 짧고 절제된 어감, 고요함·집중·차분한 신뢰감을 의도한다. 검증되지 않은 어원이나 상표 독점성을 주장하지 않는다. Brief는 장전·장후와 앞으로 확인할 변수를 포괄하며, 필요한 맥락을 무조건 짧게 줄인다는 뜻이 아니다.

개인을 위해 정돈된 정보를 준비해 주는 프리미엄 서비스의 세심함과 절제된 고급스러움을 지향한다. 특정 금융사의 디자인·문구를 복제하거나 금색 장식·VIP 문구로 대신하지 않는다. 실제 투자기관이나 전문 자문 서비스인 것처럼 표현하지 않는다. 기본 테마는 아래 다크 방향을 따르며, 구체적인 색상·서체·상세 레이아웃은 10절을 초기 구현 기준으로 채택했다. 구현 후 실제 내용과 화면을 보며 조정한다.

### 기본 테마 — 다크 채택

- 초기 기본 화면은 어두운 배경의 다크 테마로 한다. 사용자는 다크를 선호하며 기기 설정을 따라야 할 중요한 이유가 없다면 다크를 선택하겠다고 밝혔다. 현재 제품 요구에서 자동 전환을 필수로 할 사유가 확인되지 않아 해당 선호를 반영한다.
- 기기 설정을 따르는 방식은 사용자의 시스템상 밝기 선호를 존중하는 장점이 있다. 이를 가치 없는 기능으로 취급하지 않되, 라이트 테마와 기기 설정에 따른 자동 전환을 초기 필수 범위에 포함하지 않는다. 다크가 모든 독자·환경에서 더 읽기 좋다고 가정하지 않는다.
- 가독성 검증 제안: 일반 텍스트는 배경과 4.5:1 이상, 큰 텍스트는 3:1 이상, 식별에 필요한 조작 요소·정보 그래픽은 인접 색상과 3:1 이상의 대비를 확보한다. 본문뿐 아니라 보조 글씨, 출처, 차트 축·범례, 선택·포커스 상태를 확인하며 실제 예외와 적용 범위는 아래 기준을 따른다. 대비 수치만으로 전체 접근성이나 읽기 편의가 검증된 것으로 보지 않는다.
- PC·모바일의 실제 화면에서 긴 본문과 수치·차트의 가독성을 확인하고 팔레트를 조정한다. 2026-11-01 사용자는 초기 화면의 강한 대비가 의도한 고급스러운 블랙과 다르다고 피드백했고, 첫 수정에도 신문 같은 분위기와 나빠진 가독성을 지적했다. 그라디언트는 과하면 저렴해 보이지만 잘 사용하면 좋다는 의견을 제시했다. 대비를 낮추는 것만으로 고급스러움을 해결하지 않으며, 글자 선명도와 표면의 깊이를 함께 조정한다. 현재 구현은 10절, 실제 검증 범위는 기술 설계 12절을 따른다.

## 3. 초기 범위와 콘텐츠 기준 — 확정

- 2026-11-24 사용자 결정으로 미국 거래일마다 시장 전체 중심의 장후 브리핑 한 편을 발행한다. 별도 장전 브리핑의 신규 발행은 중단하고 기존 장전 보고서의 열람·정정 이력은 보존한다. 관리자의 매회 발행 승인을 필수로 두지 않는다. 실제 운영 배포 승인은 별개이다.
- 개인 관심 종목 설정은 초기 구현에서 제외한다. 후속 확장을 막지 않도록 고려하되 개인화 시스템을 미리 구현하지 않는다.
- 분량이나 읽기 시간을 고정하지 않는다. 사건이 적으면 억지로 늘리지 않고, 중요한 사건이 많으면 필요한 맥락을 유지한다. 핵심부터 읽고 필요할 때 상세를 확인할 수 있어야 한다.
- 지수·섹터·주요 기업의 움직임과 관련 사건의 의미는 장후 결과에서 설명한다. 주요 예정 이벤트·실적·어닝콜은 별도 안내 구역에서 시각·내용·간단한 설명과 주목할 이유 한 문장 정도로 정리한다. 예정 안내에 상세 전망이나 결과별 시나리오를 의무적으로 붙이지 않는다.
- 특정 영상의 스타일이나 중요도 표기를 복제하지 않는다. 빅테크·엔비디아·샌디스크·마이크론 등은 시장에 영향을 줄 수 있는 기업의 예시이며 고정된 전체 목록이 아니다.
- 확인된 사실, 출처의 해석, AI 추론을 구분한다. 자료 기준 시각, 작성·발행 시각, 출처를 확인할 수 있게 한다. 확인하지 못한 수치·사건을 만들거나 시장 움직임의 원인을 단정하지 않는다.
- 차트·표는 주요 지수의 일별 추이·섹터별 등락 등 전체 흐름을 이해하는 자료를 중심으로 한다. 사건 전후 장중 차트는 초기 필수 범위에서 제외한다. 금리 등 필요한 상황 수치는 해당 자료 기준 시점의 관측만 제공하며, 공급원은 별도 선정한다. 별도 장전 선물 현황의 갱신을 약속하지 않는다. 장식용 차트와 가짜 실시간 숫자를 사용하지 않는다.
- 한 보고서 안에서 **장후 결과 / 예정 이벤트 안내**를 구분한다. 장후 결과는 정규장과 장후의 확인된 사건·실적·콜·반응을 설명한다. 예정 안내는 장후부터 다음 거래일이 열리기 전까지와 다음 거래일 장중의 중요한 일정을 다룬다. 주말·휴장일을 건너뛰어 바로 다음 실제 거래일까지를 포함하며, 이미 발생해 확인한 사건은 결과 구역에서 다룬다. 상세 시간 범위와 형식은 7절을 따른다.

### 사실과 원인 해석 — 방향 확정, 표시 방식은 설계 중

- 확인된 가격·수치·사건과 그 움직임의 원인에 대한 해석을 구분한다. 시장 움직임의 주된 원인을 명확히 특정하지 못한 경우에도 브리핑을 발행한다.
- 근거가 뚜렷한 경우에는 해당 사건이 시장에 미친 영향을 설명한다. 근거가 제한적이면 자료로 뒷받침할 수 있는 가능한 해석을 제시하고 확신의 정도와 한계를 문장에 드러낸다. 충분한 근거가 없으면 주된 촉매를 확인하지 못했다고 명시한다.
- 원인을 찾지 못한 상태를 원인이 존재하지 않는다는 사실로 단정하지 않는다. 확인한 자료의 범위와 기준 시각을 함께 고려한다.
- 가능한 해석에도 가격 흐름, 거래량·수급 자료, 사건 전후의 반응, 관련 보도·분석 등 확인 가능한 근거를 연결한다. 단순히 “가능성이 있다”를 붙이는 것만으로 근거 없는 설명을 허용하지 않는다.
- 언론·분석가의 해석을 인용하면 누가 어떤 근거로 해석했는지 구분한다. AI 자체의 추론은 이를 확정 사실이나 출처의 주장으로 바꾸어 표시하지 않는다. 같은 보도를 재전재한 여러 기사를 독립적인 검증으로 세지 않는다.
- 차익실현, 포지션 조정, 강제청산 등 투자자의 행동을 원인으로 제시할 때는 그 해석을 뒷받침하는 자료가 필요하다. 전일과 반대 방향으로 움직였다는 이유만으로 특정 투자자의 거래 동기나 반대매매 발생을 확정하지 않는다.
- 자료 미확보·출처 간 불일치와 원인 해석의 불확실성을 별도로 알린다. 가격이 확인된 브리핑에서 원인 해석만 불확실한 경우, 모든 수치까지 미확인인 것처럼 표현하지 않는다.

- 자동 검사는 출처·시간·수치 불일치와 미확인 표시 누락 등을 점검하는 수단으로 설계한다. 출처 링크나 완곡한 표현만으로 사실성과 인과관계가 보장된 것으로 간주하지 않는다.

### 독자와 설명 수준 — 확정

- 본인이 주로 읽는 브리핑이며, 기본 투자 지식을 바탕으로 시장의 맥락을 이해하려는 독자를 기준으로 쓴다. 서비스는 공개하되 금융 입문 교육을 주목적으로 구성하지 않는다.
- 사건의 의미, 시장에 영향을 주는 경로, 다음 확인 조건에 집중한다. 이해에 필요한 낯선 용어는 해당 맥락에서 짧게 풀어 설명한다. 모든 기본 용어를 매번 설명하거나 용어 해설 때문에 본문 흐름을 끊지 않는다.
- 포트폴리오를 검토하는 방문자도 서비스의 목적과 정보 구성을 파악할 수 있어야 하지만, 이를 위해 실제 사용자의 브리핑을 입문 강의로 바꾸지 않는다.

### 기기 대응 — 확정

- PC와 스마트폰을 모두 실제 사용 환경으로 고려한다. 어느 한쪽에서만 완전한 내용을 읽을 수 있는 구조로 만들지 않는다.
- 핵심 요약, 상세 분석, 필요한 용어 설명, 출처와 자료 미확보 안내를 두 환경에서 모두 확인할 수 있어야 한다. 차트·표와 탐색 방식의 구체적인 배치는 아래 제안을 검토해 정한다.

## 4. 발행 시각과 운영 정책

미국 동부시간을 기준으로 발행 일정을 계산하고 한국시간으로 보여준다. 고정 UTC 오프셋이나 고정된 여름·겨울 월 구분에 의존하지 않도록 날짜에 따른 서머타임을 반영한다.

### 리포트의 날짜·시간 표시 — 2026-11-24 사용자 확정

- 독자가 읽는 요약·본문·차트·예정 이벤트·출처 게시 시각은 **한국시간(KST)을 먼저 쓰고 원본 시각을 함께 표시**한다. 같은 날 후속 사용자 결정으로 앞선 KST 단독 기본 표기를 변경했다. 상단에 “한국시간(KST)을 먼저 표시하고 확인된 원본 시각을 함께 제공합니다”라고 안내한다. 표시 형식은 **`2026-11-21 08:02 KST (2026-11-20 18:02 EST)`**로 통일한다. 두 날짜는 `YYYY-MM-DD`, 시각은 24시간제 `HH:mm`을 쓴다. 괄호 안에는 날짜·시각·시간대만 두고 `관측 원문` 같은 역할 설명, `미국 동부`, EST/EDT와 중복되는 UTC 오프셋은 붙이지 않는다. 게시·관측·예정·발생의 의미는 문맥·항목 이름과 내부 검증 정보에 유지한다. 긴 보조 시각은 다음 줄에 배치할 수 있다.
- 원문의 미국 동부시간은 해당 날짜에 맞춰 EST(미국 동부표준시·UTC−5) 또는 EDT(미국 동부일광시간·UTC−4)로 식별한다. UTC·다른 지역의 원문은 확인된 원래 시간대대로 표시하며 임의로 미국 동부시간으로 바꾸지 않는다. **원본 시간대가 따로 없고 UTC 값이 있으면 UTC 값을 원본 표시 기준으로 사용**한다(같은 날 후속 사용자 지시). 오프셋을 포함한 저장값은 같은 순간의 UTC로 정규화해 쓸 수 있다. 이 경우 별도의 ‘원본 시간대 미확인’ 문구를 반복하지 않는다. 숫자 오프셋만으로 국가·도시를 추측하지 않는다.
- 자체 발행·정정·수집 확인 시각은 외부 원문 시각이 없으므로 KST로 표시한다. 자료 마감·정규장 폐장처럼 운영·거래소 규칙으로 정한 시각에는 같은 간결한 형식으로 한국시간과 미국 동부시간을 병기한다. 자료 마감·폐장이라는 항목 이름으로 계산 기준임을 구분하며 이를 원문 시각으로 가장하지 않는다.
- 시각은 한국 날짜와 함께 표시한다. 같은 한국 날짜임이 문맥상 분명한 문장 안에서는 날짜 반복을 줄일 수 있지만, 날짜가 바뀌는 지점·예정 일정·표·차트에는 해당 한국 날짜를 명시한다. 미국 현지의 ‘금요일 오후’를 한국 날짜·시각과 섞지 않는다.
- 보고서 회차의 **미국 거래일**은 별도 식별 정보로 유지한다. 예를 들어 “미국 거래일 2026년 11월 20일”과 “자료 마감 11월 21일 09:30 KST”는 서로 다른 역할이다. 원문의 날짜만 확인된 사실을 근거 없이 한국 날짜로 바꾸지 않고 ‘미국 거래일’ 또는 ‘원문 게시일’임을 밝힌다.
- 서머타임은 각 사건·발행 시점의 날짜에 맞춰 `America/New_York`에서 `Asia/Seoul`로 변환한다. 고정 13·14시간 덧셈이나 현재 날짜의 서머타임 상태를 과거·미래 일정에 공통 적용하지 않는다. 주말 사이 서머타임이 바뀌면 마감 시각과 다음 일정 각각을 따로 변환한다.
- 원본 날짜·시간대·UTC 오프셋과 정확도를 보존한다. 시각 없는 날짜·장전/장후 범위에는 임의의 시·분을 만들지 않는다. 서머타임 전환 때 중복되거나 존재하지 않는 현지 시각, 시간대가 불명확한 자료는 추가 근거로 확인하며 확인 전에는 확정 시각으로 표시하지 않는다.

아래 표의 미국 동부시간은 운영 계산 기준이고, 독자 화면에는 한국 날짜·시간을 먼저 표시한 뒤 필요한 원본·계산 기준을 구분해 병기한다. 발행 일정 자체는 이번 표시 정책으로 바꾸지 않는다.

| --- | --- | --- | --- |
| 장후 | 대상 거래일 19:30 | 다음 날 08:30 | 다음 날 09:30 |

- 위 시각은 사용자가 선택한 목표 발행 시각이다. 조사 시작·자료 확인 마감·생성 완료 시각이나 어닝콜 시작·종료 시각을 뜻하지 않는다.
- 장후는 한국 표준시 기준 09:30을 수용하기로 했다. 한국 증시 개장 전에 제공되는 서비스로 약속하지 않는다.
- 모든 주요 콜이 종료되고 원문까지 확보된다는 보장은 없다. 자료 확인 범위와 기준 시각을 표시해야 한다.
- PC가 꺼져 있어도 생성과 수집이 원격으로 실행되어야 한다. 현재 연동 경로와 정시 실행 가능성은 검증 전이다. 일부 주요 어닝콜 자료가 늦는 경우의 대기 기준은 아래와 같으며, 수집·생성 자체의 실패 처리는 별도로 설계한다.
- 주말·휴장일의 발행 여부는 아래 정책을 따른다. 조기 폐장일에도 기존 목표 시각을 유지하며 11절의 확정 정책을 따른다.

### 주말·휴장일 — 확정

- 미국 거래일에 대응하는 장후 브리핑만 발행한다. 미국장이 열리지 않는 주말·휴장일 자체에 대한 별도 브리핑은 발행하지 않는다.

## 5. 다음 브리핑 발행 예정 안내

### 확정된 요구사항

- 브리핑 목록에서 다음 브리핑이 언제 공개될 예정인지 미리 확인할 수 있어야 한다.
- 다음 장후 회차의 대상 거래일과 예정 날짜·시각을 이해하기 쉽게 안내하고 서머타임을 반영한다. 미국 주말·휴장일의 미발행 정책과 거래일에 대응하는 한국 발행일을 구분해 다음 회차를 계산한다.
- 목록 상단에 간결한 예정 안내를 두고 이미 발행된 브리핑과 구분한다. 안내에는 “발행 예정”이라는 표현을 사용한다.
- 서버를 다시 켜면 목표 시각이 지난 가장 최근 정규 회차 하나만 당시의 확인 가능한 자료로 발행할 수 있다. 준비가 시작됐어도 목표 시각 전인 다음 회차는 이 판단에서 제외한다. 최신 회차가 이미 발행됐으면 그 이전 회차로 돌아가지 않는다.
- 앞선 미발행 장후 회차는 실패로 마감하고, 아카이브와 회차 상세에 미국 거래일·장후·발행 예정 시각·마감 사유를 고정 양식으로 표시한다. 이 안내에는 시황이나 AI 생성문을 넣지 않는다. 관리자는 회차별 이력과 안내 공개 여부를 확인할 수 있다.
- 예정 시각을 넘겼고 아직 마감되지 않은 미발행 회차는 지연 상태를 안내한다. 확인되지 않은 완료 예상 시각을 만들지 않으며, 실제 상태를 확인할 수 있을 때만 “작성 중” 등의 표현을 사용한다.
- 지금은 요구사항과 화면 방향을 기획에 남긴다. 최종 문구, 색상, 위치, 크기와 상세 UI·UX는 추후 화면 설계에서 다듬는다.

### AI 제안 — 상세 설계에서 검토

- 예정 안내가 최신 글을 읽는 흐름을 방해하지 않게 배치한다. 미발행 항목을 이미 읽을 수 있는 글처럼 표시하지 않는다.
- 표시 예시: “다음 브리핑 · 장후” / “내일 오전 9:30 발행 예정” / “한국시간(KST) · 11월 4일”. 이 날짜와 문구는 UI 설명용 예시이며 실제 발행 일정이 아니다.
- 상대 날짜인 오늘·내일과 절대 날짜를 함께 제공한다. 장후 브리핑이 다루는 미국 거래일과 한국 발행일이 하루 다를 수 있으므로 혼동하지 않게 표시한다.
- 상대 날짜는 한국시간 기준으로 계산한다. 서버나 방문자의 기기 시간대가 달라도 한국시간 안내의 의미가 달라지지 않아야 한다.
- 지연 문구 예시: “장후 브리핑 발행이 지연되고 있습니다.” 예정 시각을 넘긴 회차에 미래형 안내나 음수 카운트다운이 남지 않게 한다.
- 새 브리핑이 실제로 공개되면 읽을 수 있는 목록 항목으로 제공하고 다음 유효 일정으로 안내를 갱신한다. 누락된 회차가 있으면 그 상태를 숨긴 채 다음 일정만 보여주지 않도록 상세 동작을 정한다.
- 조기 폐장일에도 목표 발행 시각은 유지한다. 임시 휴장 등으로 예정 일정을 확정할 수 없으면 미정임을 보여준다.
- 모바일에서도 세션·날짜·시각을 쉽게 읽게 하고, 상태를 색상만으로 구분하지 않는다. 장식적인 초 단위 카운트다운은 기본 요구사항에 포함하지 않는다.

### 이 기능의 검증 항목 — 제안, 구현 후 확인

- 새 발행 대상은 장후만 계산하며, 대상 거래일과 예정 날짜·시각이 확정 발행 규칙과 일치한다. 기존 장전 보고서의 조회·정정은 계속 가능하다.
- 서머타임 전환 전후, 한국 자정 전후, 미국 거래일과 한국 발행일이 다른 경우에도 날짜와 시각이 일치한다.
- 발행 전·발행 지연·발행 완료·예정 미정 상태에서 오해를 만드는 문구나 읽을 수 없는 글 링크를 표시하지 않는다.
- 미국 휴장일 미발행, 금요일 장후의 한국 토요일 발행, 휴장 기간의 주요 사건을 다음 거래일 장후에 통합하는 동작을 검증한다. 예정 안내의 범위가 다음 실제 거래일의 폐장까지 이어지는지, 조기 폐장일에도 목표 발행 시각이 유지되는지 확인한다. 모바일과 데스크톱에서 안내와 최신 브리핑을 구분해 읽을 수 있다.

## 6. 운영비와 생성 방식 — API 시작·교체 가능한 구조 채택

- 무료 구성을 우선 검토하되 무료만을 필수 조건으로 삼지 않는다. 운영비 지출을 고려할 수 있으며 현재 고정된 월 비용 상한은 두지 않는다.
- 2026-11-17 사용자 선호: 정상적인 조사·생성 품질을 제한하지 않을 만큼 비용 여유를 두고, 비정상적인 반복·폭주에 대비한 제한을 원한다. 후속 답변에서 첫 시험의 회차·하루·누적 비상 금액안을 수락했다. 확정 금액과 포함 범위는 기술 설계 8절에서 관리한다. 운영 모델·공급원 계약·외부 계정 설정까지 확정한 것은 아니다.
- 유료 항목은 필요성, 예상 비용과 산정 근거, 제공되는 가치·제약을 제시한 뒤 사용자가 내용을 보고 결정한다. 구체적인 서비스 가입·결제·유료 사용은 공통 승인 기준을 따른다.
- 초기에는 서버에서 API를 사용해 조사·생성한다. 생성 부분을 공통 브리핑 데이터·검증·저장·화면에서 분리해 모델이나 생성 경로를 나중에 교체할 수 있게 한다. 초기에는 API 경로 하나만 구현하며 Work/Drive 연결 확인을 선행 조건으로 두지 않는다.
- 모델·검색·데이터·서버 등 필요한 비용은 실제 후보 구성에 맞춰 확인한다. 기술 설계에 가정에 따른 월 비용 예시를 정리했다. API 방식 채택은 특정 모델·요금제·유료 사용의 승인이 아니며 실제 사용량은 아직 측정하지 않았다.
- 생성 경로의 적합성은 출처와 콘텐츠 품질, PC가 꺼진 상태의 실행, 수집·발행 일정과 지연 대응, 연동·관리 부담, 실제 운영비로 확인한다. 채택한 설계도 실제 기능·품질이 검증된 상태는 아니다.
- 기술 구성과 교체 경계는 [기술 설계](TECH_SPEC.md)에서 관리한다. Work/Drive는 추후 전환을 검토할 때 실제 연동 가능성을 확인할 후보로 남긴다. 교체 가능성은 모든 경로가 설정 하나로 바뀐다는 뜻이 아니다.

## 7. 브리핑 목차와 읽기 흐름 — 확정 사항과 AI 제안

첫 화면·지난 글 탐색, 장후 어닝콜 통합, 핵심 요약을 먼저 두고 나머지는 중요도에 따라 배치하는 원칙을 확정했다. 중요도 판단의 세부 기준은 AI 제안이며, PC·모바일 화면 배치는 10절을 초기 기준으로 채택하고 구현 후 조정한다.

### 첫 화면과 지난 브리핑 탐색 — 확정

- 첫 화면은 가장 최신인 공개 보고서 하나를 최우선으로 보여주고 바로 읽도록 안내한다. 장전·장후를 나란한 선택지로 강조하지 않으며, 나머지 보고서는 아래 기록 목록에서 참고한다. 다음 발행 안내는 보조 정보로 제공한다. 이는 2026-11-01 사용자가 최신 보고서의 우선순위를 명시한 후속 기준이다.
- 장전·장후를 구분하고 각 브리핑의 대상 날짜를 확인할 수 있게 한다. 다음 발행 안내와 미발행·지연 상태는 5절의 기준을 따른다.
- 지난 글은 날짜와 장전·장후 구분으로 찾는다. 키워드·본문 검색은 초기 범위에서 제외한다.
- 메인에 표시한 최신 회차는 지난 브리핑 목록에 중복 표시하지 않는다. 같은 거래일의 다른 회차는 유지한다. 목록의 날짜·세션 필터와 페이지 이동에서도 이 기준을 적용하며 메인은 최신 보고서로 유지한다.
- 필터의 세부 조작 방식, 빈 목록 안내, PC·모바일의 상세 배치는 후속 화면 설계에서 구체화한다. 날짜 필터의 기준도 대상 미국 거래일과 한국 발행일을 혼동하지 않게 표시한다.

### 장후 어닝콜 통합 — 확정

- 주요 어닝콜은 장후 브리핑과 같은 글 안의 별도 구역으로 제공한다. 초기 범위에서 어닝콜 상세 글을 따로 나누는 방식을 채택하지 않는다.
- 시장 전체에 영향을 주는 중요한 내용은 상단 핵심 요약에도 반영한다.
- 정규장 결과와 장후 어닝콜·시간외 반응은 구분해 표시한다. 장후에 확인된 정보가 정규장 움직임의 원인이었던 것처럼 서술하지 않는다.

### 본문 순서 — 핵심 요약 고정, 중요도에 따른 가변 배치

- 핵심 요약을 본문의 최상단에 두고 장후 결과와 예정 이벤트 안내를 명확히 구분한다. 장후 결과 안의 주요 이슈 순서는 중요도와 설명 흐름에 따라 조정한다.
- 주요 어닝콜, 시장의 큰 변화, 흐름 변화에 관한 설명은 장후 결과에 배치하고, 예정 이벤트는 별도 안내 구역에서 짧게 제공한다. 기존의 분량·불필요한 반복 제한과 중요한 자료 미확보 표시 기준은 유지한다.
- 가변 배치는 회차 작성 시 적용한다. 발행 후 새 정보와 오류 정정은 8절의 정책을 따르며, 열람할 때마다 본문 순서를 임의로 바꾸는 기능으로 확장하지 않는다. 정규장과 장후 반응, 관측 사실과 예정·해석의 구분도 유지한다.

### 가변 배치의 상세 기준 — AI 제안, 실제 콘텐츠 검증 전

- 중요도는 시장 전체·주도 섹터에 대한 영향 범위, 확인된 반응의 크기, 예정 시점의 가까움, 기존 전망·흐름을 바꿀 새 정보 등을 함께 보고 판단한다. 단순 기사 수나 자극적인 제목으로 순서를 정하지 않는다. 항목별 가중치나 점수는 아직 정하지 않았다.
- 중요도와 근거의 확실성을 구분한다. 중요한 예정 이벤트는 결과가 미정이어도 앞에 둘 수 있지만, 출처 불명 주장이나 확인되지 않은 원인을 중요한 사실로 승격하지 않는다. 사실·해석·한계 표시는 3절을 따른다.
- 구역의 분류와 핵심 명칭은 일관되게 유지하고, 해당 회차의 실제 배치에 맞춘 이동 목차를 제공하는 안을 검토한다. 매번 순서가 달라져도 원하는 내용을 찾을 수 있게 한다. 비슷하게 중요한 항목은 맥락과 시간 관계가 자연스러운 순서로 배치하고 같은 사건의 설명을 불필요하게 반복하지 않는다.
- 평온한 날, 큰 시장 변화가 있는 날, 주요 어닝콜이 중심인 날, 중요한 발표를 앞둔 날의 샘플로 요약 우선·중요 이슈 배치·시간 구분·필수 정보 누락 여부를 확인한다. 9절에 가상 상황별 구성 예시를 제시했다. 실제 시황 생성이나 가독성 검증을 수행한 것은 아니다.

### 장후 결과와 예정 이벤트 안내 — 2026-11-24 사용자 확정

| 구역 | 내용과 설명 수준 |
| --- | --- |
| 핵심 요약 | 시장이 어떻게 마감했고 무엇이 중요했는지 먼저 전달 |
| 장후 결과 | 지수·업종·주요 사건·확인된 실적과 어닝콜·시간외 반응을 연결해 설명. 확인한 결과와 해석의 범위를 구분 |

- 예정 범위는 해당 장후부터 다음 실제 미국 거래일의 정규장 종료까지다. 안내에는 자료 마감 시점에 아직 예정인 사건만 싣고, 이미 발생해 확인한 사건은 장후 결과로 보낸다. 금요일 장후에는 주말과 다음 거래일 장중을 포함한다. 월요일이 휴장이면 다음 실제 거래일까지 이어지며 조기 폐장일의 끝은 실제 폐장 시각을 따른다.
- 예정 시각은 4절에 따라 한국 날짜·시간을 먼저 표시하고 원본 날짜·시간대와 함께 제공한다. ‘장전’만 확인했으면 변환 가능한 한국 날짜 범위와 원문의 미국 거래일·장전이라는 범위를 구분해 적고 정확한 시·분을 추측하지 않는다. 확인한 중요 일정이 없거나 조사 범위가 제한적이면 그 상태를 짧게 밝힌다. ‘확인하지 못함’을 ‘일정 없음’으로 바꾸지 않는다.
- 예정 안내는 시간·이벤트명과 필요한 설명을 항목별로 구분해 빠르게 훑어볼 수 있게 한다. 정확성·중요한 정보·독자의 이해를 분량보다 우선하며, 행사 내용과 주목할 이유를 이해하는 데 필요한 맥락은 충분히 설명한다. 반복과 당연한 주의 문구는 줄이고 발표 전 결과를 쓰지 않는다. 세부 예상치나 중요도 점수를 필수 필드로 만들지 않는다. Codex 비교 원고의 길이는 간결함을 위한 참고이며 상한이 아니다. 글자 수·문장 수를 일률적으로 제한하지 않는다.
- 장후 결과 구역 안의 세부 순서는 핵심 요약 우선과 중요도에 따른 가변 배치 원칙을 따른다. 장후 어닝콜은 같은 글 안에서 정규장과 구분한다.
- 주요 수치·차트에는 대상·단위·기간 또는 기준 시각·출처를 표시한다. 선물, 현물 지수, ETF를 혼동하거나 다른 시간대의 변화를 같은 기준으로 비교하지 않는다. 사용할 지표와 데이터 공급원은 아직 선정하지 않았다.
- 사건의 설명은 3절의 사실·원인 해석 기준을 따른다. 출처와 해당 항목의 자료·해석 한계는 수치나 주장 가까이에서 확인할 수 있도록 배치하는 안을 제안한다.
- 상단 요약의 항목 수와 모든 구역의 분량을 고정하지 않는다. 변화가 없는 구역은 짧게 처리하거나 생략할 수 있지만, 중요한 자료가 미확보된 사실을 이슈가 없는 것으로 숨기지 않는다.
- 시장 흐름 점검은 새로운 근거가 있을 때 중심적으로 다룬다. 새로운 정보 없이 기존 해석을 매회 길게 반복하지 않는다.
- 예정 안내의 간결한 형식과 범위는 위 사용자 확정 기준을 따른다. 구체적인 소재 선택과 설명 분량은 새 기준 원고를 읽고 조정한다.

### PC와 모바일의 초기 배치 기준

- 공통: 제목, 대상 미국 거래일과 세션, 발행·자료 기준 시각, 필요한 자료 미확보 안내를 확인한 뒤 핵심 요약과 본문으로 이어진다. 차트는 관련 설명 가까이에 둔다.
- PC: 읽기 좋은 본문 폭을 유지하고 옆에 구역 이동용 목차를 둔다. 화면이 넓다는 이유로 많은 글과 차트를 동시에 펼쳐 밀도를 높이지 않는다.
- 모바일: 핵심 요약과 차트를 한 열로 배치하고 간단한 목차로 긴 본문 안에서 이동할 수 있게 한다. 세부 표와 차트는 화면 폭에 맞춰 재배치하거나 확대해 확인할 수 있게 한다.
- 필요한 용어 설명은 짧은 본문 설명이나 선택해서 열 수 있는 보조 설명을 검토한다. 모바일에서 사용할 수 없는 마우스 올리기 동작에만 의존하지 않는다.
- 두 환경 모두 핵심 내용·출처·자료 미확보 표시가 유지되어야 한다. 실제 화면·가독성의 확인 범위와 남은 검증은 기술 설계 12절을 따른다. 일부 화면 검증을 전체 접근성 준수 완료로 간주하지 않는다.

## 8. 발행 후 보완과 관리자 운영

### 추가 정보와 오류 정정 — 확정

- 발행 후 확보한 어닝콜 자료나 새로 나온 중요한 정보는 다음 발행 대상 브리핑에 반영한다. 기존 글은 해당 회차의 자료 기준 시점에 확인된 내용을 유지하며, 새로운 정보가 생길 때마다 덧붙이는 방식은 초기 범위에서 제외한다.
- 기존 글의 잘못된 수치·사실은 다음 회차로만 넘기지 않고 해당 글에서 정정한다. 독자가 정정 내용을 확인할 수 있게 변경 내용·이유와 정정 시각을 표시한다.
- 뒤늦게 확인된 새 정보와 당시 내용의 오류를 구분한다. 정정 과정에서 이후 사건을 원래 알고 있었던 것처럼 소급해 서술하지 않는다.

관리자 인증은 Google 로그인으로 정하고 운영자 한 명만 허용한다. 공개 브리핑 열람에는 로그인을 요구하지 않는다. 인증·권한과 환경 분리의 세부 기준은 [기술 설계](TECH_SPEC.md)를 따른다.

### 관리자 직접 편집 — 사용자 이용 의향과 AI 제안

- 사용자는 본문을 직접 편집할 계획이 없으며, 필요성이 낮다면 편집기를 생략해도 된다고 밝혔다. 실제 편집 필요 빈도는 샘플 생성과 운영 전에는 확인할 수 없다.
- AI 제안: 초기에는 문장·수치·출처를 자유롭게 고치는 본문 편집기를 제외하고, 발행 상태 확인, 실패 작업 재시도, 오류 정정 요청, 공개·비공개 전환에 집중한다. 이는 사용자 의향을 반영한 범위 제안이며 세부 동작까지 확정된 것은 아니다.
- 오류 정정 요청은 잘못된 항목과 근거를 바탕으로 자료를 재확인해 수정본을 만드는 흐름을 검토한다. 단순 재생성만으로 오류가 해결된다고 가정하지 않으며, 정정 표시와 자료 기준 시점을 유지한다. 정확성을 회복하지 못한 글은 비공개로 전환할 수 있는 방안을 검토한다.
- 관리 화면의 재수집·재생성, 수정본 검증과 교체 방식은 채택한 API 경로를 기준으로 기술 설계에 정리한다. 2026-11-18 실제 로컬 Google 로그인과 인증된 브라우저에서 더미 발행·재시도·정정·비공개/복구·보관 흐름을 확인했다. 실제 외부 수집·생성 품질과 운영 환경 검증은 남아 있으며 상세 범위는 기술 설계 12절을 따른다.

### 운영 알림 — 대상·채널·발송 기준 확정

- 텔레그램은 운영자가 장애에 대응할 때만 사용한다. 리포트와 DB 백업의 예정·정상 완료 메시지는 생략한다. 수집·생성 실패, 지속되는 기술적 발행 지연, 백업 실패나 누락이 의심되어 확인이 필요한 경우를 알린다. 독자는 공개 목록에서 발행 예정·지연 상태를 확인할 수 있다.
- 운영자는 자동 발행과 자동 DB 백업을 각각 켜고 끈다. 한쪽을 꺼도 다른 쪽의 작업과 예외 알림은 계속된다. 자동 백업을 끄면 백업 실행·누락 점검·백업 알림 재시도가 함께 멈춘다. 로컬에서는 두 자동 작업을 모두 끈다.
- 복구할 수 없는 실패와 기술적 이유의 목표 시각 대비 15분 이상 발행 지연을 텔레그램으로 알린다. 같은 문제의 반복 알림을 제한하고, 합의된 어닝콜 자료 대기를 기술적 실패와 구분한다. 재시도 소진·발송 실패 등의 상세 처리는 기술 설계 6절을 따른다.
- 운영 알림 채널은 텔레그램 봇과의 개인 대화로 정한다. 사용자는 구현 난이도 차이가 크지 않으면 확인하기 편한 텔레그램을 선호한다고 밝혔다. 운영자 한 명에게 알림을 보내는 범위에서는 이메일 대비 큰 구현 부담이 추가되지 않는다는 공식 API 문서 기반 판단에 따라 채택했다. 2026-11-21 운영자가 개인 대화에서 시험 메시지를 받았다. 운영 서버의 자동 장애 알림은 배포 후 검증한다.
- 초기 범위는 운영자에게 알림과 관리 화면 링크를 보내는 것이다. 텔레그램 안에서 대화하거나 운영 명령을 실행하는 기능은 포함하지 않는다. 봇 생성·대화 시작·수신 대상 등록 등 초기 설정과 서버 측 발송 방식은 기술 설계 및 구현 단계에서 구체화한다.
- AI 제안: 알림에는 대상 회차, 확인된 문제와 현재 상태, 관리 화면 링크를 담고 비밀정보나 전체 실행 로그를 넣지 않는다. 장애 감지·재시도·중복 알림 억제는 채널 선택과 별도로 설계한다.

## 9. 콘텐츠 제작 기준

2026-11-26 사용자는 자료수집 평가에서 Codex가 찾았던 자료와 일치하는지를 기준으로 삼지 않도록 명확히 했다. 필요한 시장 정보와 예정 이벤트의 충족, 실제 원문과 시점의 정확성으로 평가한다. 기존 조사에 없던 유효한 근거도 인정하며, 여러 모델이 공통으로 놓친 정보가 있을 가능성도 확인한다. 수집 자료의 개수나 네 결과의 합집합 자체를 정답으로 취급하지 않는다. 구체적인 시험 조건은 [자료수집 비교 시험](RESEARCH_TRIAL.md)을 따른다.

장후판은 아래 기준으로 Codex 편집본과 API 생성본을 검토한다. 기존에 ‘수작업본’이라 부른 11월 20일 보고서는 Codex에서 사용자 피드백을 받아 여러 차례 수정한 결과다. 2026-11-23 사용자는 이 글이 현재까지 나온 결과 중 선택한 비교 대상이며, 최종 정답이나 품질의 상한이 아니라고 명확히 했다. 더 이해하기 쉬우면서 근거도 충실한 결과가 나오면 비교 기준을 갱신한다. 기존 편집본의 문장·목차·사건 순위를 재현하는 것을 목표로 삼지 않는다. 작성 조건과 수정 횟수가 다른 두 결과의 차이를 모델 자체의 성능 차이로 단정하지 않는다.

11월 20일 장후 회차에서 합의한 작성 기준을 첫 Sol 시험에 적용했다. Codex 편집본은 결과 비교용으로 보관하고 모델 입력에서는 제외한다. 2026-11-23 후속 요청으로 중요한 내용을 선별·강조하고 의미를 연결하는 기사형 해설 방향을 아래 작성 기준에 반영했다. 이어지는 공통 편집 세부안과 가상 구성은 기존 제안이다.

2026-11-24 새 구성의 진행 순서는 **코딩·검증과 문서 정리 → Codex 기준 원고 초안 작성 → 다음 단계에서 사용자와 원고 조정 → 조정 완료 후 별도 단계에서 API 생성·비교와 세부 조정**이다. 이번 작업은 기준 원고 초안까지이며 유료 API 생성은 포함하지 않는다. 아래 번호 원칙은 기존 `quality-v2` 비교 조건을 보존하며 장후 결과의 읽기 기준으로 사용한다. 7절의 예정 안내를 포함한 API 프롬프트 최종 반영은 원고 조정 후 새 버전으로 진행한다. 기준 원고도 더 나은 결과가 생기면 바꿀 수 있는 잠정 비교 대상이다.

2026-11-26 API 결과를 읽은 뒤 사용자는 익숙하고 자연스러운 문체와 목록형 예정 안내를 요청했다. 후속으로 보고서의 품질이 최우선이며 길이를 맞추기 위해 필요한 설명을 줄이지 않도록 확정하고 수정을 승인했다. 아래 문체·목록 보완 기준은 새 `combined-v2` 작성·보정에 적용한다. 그 아래 기존 통합 기준과 장후 작성 기준의 번호 원문은 이전 시험 요청 재현을 위해 보존한다. 새 기준과 분량에 관한 이전 표현이 겹치면 품질을 우선하는 이번 기준을 적용한다.

### 문체와 예정 목록 보완 기준

1. **정확성과 이해에 필요한 내용을 분량보다 우선한다.** 중요한 정보, 해석의 근거, 결론을 바꾸는 반대 관측이나 한계를 충분히 전달한다. 사건의 중요도와 복잡성에 따라 설명량을 조절하며, 길이에 맞추려고 핵심 맥락을 빼거나 결론을 더 확실하게 만들지 않는다. 글자 수·문장 수를 일률적으로 제한하지 않는다. 비교 원고의 길이나 구성은 참고이며 품질의 상한이 아니다.
2. **익숙하고 자연스러운 한국어 기사 문장으로 쓴다.** 누가 무엇을 했고 어떤 변화가 있었는지 구체적인 주어와 동사로 설명한다. 추상적인 명사를 겹치거나 독자가 다시 풀어 읽어야 하는 번역투·보고서투를 줄인다. 관용적으로 쓰는 금융 용어는 필요한 맥락에서 쓰고, 낯선 용어는 의미가 유지되도록 짧게 설명한다. 쉬운 말로 바꾸는 과정에서도 조건·주체·대상·비교 기준과 불확실성은 정확하게 유지한다.
3. **도입부에서 그날 가장 중요한 흐름을 잡고 본문에서 필요한 설명을 이어간다.** 요약에는 시장의 핵심 변화와 중요한 배경을 선별한다. 수치·부차적인 사건·개별 주장에만 해당하는 한계를 첫머리에 모두 모으지 않는다. 전체 해석에 영향을 주는 자료 부족은 요약에서도 분명히 밝힌다. 본문에서는 문단마다 설명할 내용을 분명히 하고, 의미를 더하는 정보에는 충분한 분량을 배정한다.
4. **예정 안내는 항목별 목록으로 쓴다.** 각 일정의 예정 시각과 이벤트명을 먼저 보여주고, 내용·간단한 설명·주목할 이유를 그 아래에 둔다. 한 일정은 독립된 항목으로 구분하며 여러 일정을 긴 해설 문단에 섞지 않는다. 독자가 무엇이 언제 예정돼 있고 무엇을 살펴볼지 이해할 만큼 설명한다. 중요한 차이나 복잡한 조건이 있으면 필요한 만큼 늘리고, 단순한 일정에는 간단한 설명을 쓴다. 사전 분석의 여러 논점을 그대로 나열하거나 발표 전 결과·새 전망을 만들지 않는다.
5. **한계는 필요한 위치에서 구체적으로 설명하고 중복을 줄인다.** 예정 사실에 관해 아직 결과가 나오지 않았다는 당연한 말이나 일반적인 경고를 매 항목에 반복하지 않는다. 실제 일정의 불확실성, 조사 범위, 해석에 필요한 조건은 독자가 판단하는 위치에서 밝힌다. 본문과 별도 한계 필드에 같은 설명을 되풀이하지 않는다. 사실·출처의 해석·AI 추론 구분과 필수 근거·한계 검증은 유지하며, 간결함을 이유로 필요한 단서를 숨기지 않는다.
6. **시각 표현을 읽기 쉽게 쓰면서 검증 가능한 근거를 유지한다.** 정확한 시각을 쓸 때는 제공된 한국시간·원본 시각 쌍을 그대로 사용한다. ‘정오’, ‘자정’처럼 특정 시각을 가리키는 표현도 원본 시간대를 밝히지 않은 채 쓰지 않는다. 발췌에만 있고 구조화된 관측·발생 시각이 없는 경우에는 근거가 확인하는 ‘장중’, ‘보도 전’ 같은 순서·구간으로 설명할 수 있다. 기사 게시 시각을 관측이나 발생 시각으로 대신 쓰지 않는다. 보정에서는 지적된 주장·필드·표현을 확인해 고치고 중요한 내용과 근거는 보존한다.

### 장후 통합 보고서 작성 기준

1. **장후 결과와 예정 이벤트 안내를 구분한다.** 아래 장후 보고서 작성 기준의 기사형 설명·근거 연결 원칙을 공통으로 적용한다. 제목과 핵심 요약은 그날 시장의 핵심 변화와 의미를 먼저 전하고, 본문은 장후 결과를 읽은 뒤 예정 이벤트 안내로 이어지게 한다.
2. **자료의 수보다 설명의 중요도에 따라 분량을 배정한다.** 시장 전반의 흐름, 중요한 개별 사건, 이를 지지하거나 제한하는 관측을 연결한다. 수치·근거를 나열하는 데 그치지 않고 독자가 무엇을 이해해야 하는지 쉬운 문장으로 설명한다. 핵심 사건은 충분히 설명하고 의미를 더하지 않는 반복·부차적 소재는 줄인다. 특정 회차의 종목·사건·섹션 수를 모든 날의 필수 틀로 만들지 않는다.
3. **정규장 결과와 장후에 새로 확인한 내용을 같은 원인처럼 섞지 않는다.** 장후 발언과 시간외 반응은 정규장 이후의 별도 관측으로 설명한다. 단순한 시간 순서에서 인과관계를 만들지 않는다. 수익률의 비교 기준을 밝혀 하루 등락과 정규장 종가 이후의 변동을 구분한다.
4. **예정 안내는 짧고 실제로 참고할 수 있게 쓴다.** 자료 마감 뒤부터 다음 실제 미국 거래일 정규장 폐장 시각까지의 중요한 실적 발표·콜·경제지표·연준 연설 등을 고른다. 폐장 시각에 시작하는 일정은 포함하고 그 이후 일정은 제외한다. 일정별 예정 시각, 내용과 간단한 설명, 주목할 이유 한 문장 정도를 제공한다. 발표 결과나 새 전망을 만들지 않고 과도한 해설로 늘리지 않는다. 주말·휴장일·조기 폐장은 해당 거래 달력에 따른다.
5. **시각은 간결한 병기 형식과 확인된 정확도를 지킨다.** `YYYY-MM-DD HH:mm KST (YYYY-MM-DD HH:mm EST)`처럼 한국시간 뒤에 원본 날짜·시각·시간대를 쓴다. 형식 예시의 날짜·시각·시간대는 실제 근거에 맞게 채운다. 날짜별 EST/EDT, 원본 시간대가 없을 때의 UTC를 적용한다. 게시·관측·예정·발생의 역할은 문맥과 근거에서 구분한다. 시·분 없는 날짜나 장전·장후 범위에 임의의 시각을 만들지 않는다.
6. **미확인 범위와 직접 근거를 필요한 위치에서 드러낸다.** 원고의 설명과 예정 안내는 자료 마감 전에 공개된 근거로 작성한다. 일정 조사 범위가 제한적이면 짧게 알리고 확인하지 못한 일정을 없다고 단정하지 않는다. 인용 연결은 문장·소제목의 구체적인 내용을 뒷받침해야 한다. 비교용 코덱스 원고의 문장을 API 작성 자료로 넣지 않고, 공통 작성 기준과 근거 자료로 독립적으로 작성한다.

### 장후 보고서 작성 기준

1. **제목과 첫 요약에서 그날의 핵심 변화와 의미를 설명한다.** 기본 투자 지식이 있는 사람이 읽는 한국어 시장 해설 기사를 쓴다. 주요 지수와 업종을 같은 거래 구간에서 비교해 시장 전반이 함께 움직였는지, 일부에 변화가 집중됐는지 살핀다. 독자의 이해를 가장 크게 바꾸는 차이를 제목에 담고, 첫 요약은 그 차이가 왜 중요한지 설명하며 본문으로 이어지게 한다. 자료가 뒷받침하는 주요 배경과 핵심 한계를 함께 전달하되 단일 원인을 만들지 않는다. 업종 자료가 없고 개별 종목만 확인했다면 그 종목들로 설명 범위를 좁힌다.
   - 비교를 다루는 소제목은 ‘이 비교를 보면 무엇을 알 수 있나?’에 쉬운 말로 답한다. 지표 이름과 수치는 결론을 이해하는 데 꼭 필요할 때만 소제목에 쓰고, 자세한 비교는 본문에서 보여준다.
   - 시장 전반의 등락을 앞세우면 원인도 그 범위에서 조사한다. 하락 업종 수와 동일가중 수익률은 매도의 폭을 보여준다. 배경을 설명하려면 당시 여러 시장에서 관측된 변화, 시장 참가자가 지목한 부담, 그 부담이 다른 업종의 주문·자금 조달·소비 등에 닿는 사례를 대조한다. 영향을 덜 받은 업종도 함께 보면 설명의 한계가 드러난다. 공통 배경을 확인하기 어렵다면 요약에서 그 한계를 밝히고, 특정 업종에 해당하는 해석은 해당 문단에 둔다.
2. **주요 사건에는 그날 새로 알게 된 내용을 담는다.** 이전에 알려진 사실, 이번에 달라진 점, 독자에게 중요한 이유를 연결한다. 실적이면 비교 가능한 전년 동기·가이던스·당시 예상치 중 의미 있는 기준을 고른다. 실적이 기록을 경신했다는 사실만으로 시장 기대를 웃돌았다고 쓰지 않는다. 다른 주요 사건이나 반대로 움직인 업종이 첫 해석의 범위를 바꾸면 함께 다룬다.
   - 먼저 당시 투자자가 무엇을 확인하려 했는지 자료에서 찾는다. 기대하던 반응이 약했거나 나타나지 않아 기존 해석이 달라졌다면 그 사건도 다룬다. 사건을 빼면 그날의 흐름을 다르게 이해하게 되는지와, 그 사건을 가격 변화의 원인으로 지목할 근거가 있는지는 따로 판단한다.
   - 중요한 사건은 그 자체의 의미가 보이는 위치와 소제목을 준다. 다른 사건의 예시나 숫자 한 줄로만 묻어 두지 않는다. 입력에 있다는 이유로 모든 공식 발표·종목·수치를 기사에 넣지 않는다. 핵심 흐름의 이해나 다음 판단을 바꾸지 않는 내용은 줄이거나 제외하되, 반대 근거와 중요한 자료 미확보를 생략해 결론을 더 확실하게 만들지 않는다.
3. **사건과 가격을 같은 시간축에서 읽는다.** 과거 회차에는 자료 마감까지 공개된 판본만 쓴다. 사건이 일어난 때, 처음 알려진 때, 가격을 관측한 때를 구분한다. 전일 종가 대비 하루 등락과 보도 직전 가격 대비 변동은 기준값이 다르다. 직전 시세가 없으면 확인된 시점·등락 기준만 쓴다. 시간외 반응은 당일 정규장 종가를 기준으로 따로 설명한다.
4. **원인을 설명하는 문장에는 그 연결을 뒷받침하는 근거를 붙인다.** 공식 발표, 취재 보도, 시장 참가자의 해석은 주체를 밝혀 쓴다. 사건 전부터 같은 흐름이 있었는지, 같은 시각 다른 종목·업종도 움직였는지 확인한다. 시간 순서만 확인되면 관측한 순서까지만 서술한다. 한 종목이 지수 등락에 기여한 크기를 제시하려면 해당 지수의 같은 기간 기여도 자료 또는 당시 비중과 지수 산식에 따른 계산 근거가 필요하다. 기여도만으로 다른 종목도 같은 이유로 움직였다고 해석하지 않는다.
   - 우려나 전망을 소개할 때는 누가 무엇을 예상했는지 밝힌다. 이를 판단하는 데 도움이 되는 당시 관측 자료가 있으면 같은 문단에 놓고, 측정 대상과 기간을 명시한다. 발표일과 관측 기간이 다르면 어느 시점까지 설명할 수 있는지 구분한다. 관측 범위를 넘어 우려가 이미 현실화됐거나 해소됐다고 쓰지 않는다. 관련 자료가 부족하면 확인 가능한 범위만 밝힌다.
   - 출처는 문장의 근거로 연결한다. 소제목에 두 가지 주장을 함께 썼다면 해당 구역의 본문과 연결 출처가 두 주장 모두를 뒷받침해야 한다. 다른 구역에 관련 수치가 있다는 사실만으로 인용을 대신하지 않는다.
5. **마지막에는 다음 거래일에 무엇을 보면 오늘의 해석이 달라질지 쓴다.** 예를 들어 일부 반도체주에 하락이 집중됐다면 다음 장에서 다른 업종까지 약세가 번지는지 살핀다. 예정된 발표를 다루면 확인된 일정과 주목할 항목을 밝힌다. 조용한 날에는 확인한 움직임과 의미 있는 확인점만 짧게 남긴다.
6. **정보를 선별하고 연결해 한 편의 읽기 쉬운 글로 다듬는다.** 중요한 내용에는 앞자리와 필요한 설명을 배정하고, 덜 중요한 내용은 짧게 처리하거나 덜어낸다. 강조는 제목·배치·설명의 깊이로 만든다. 같은 중요도로 자료를 나열하거나 굵은 글씨와 수식어로 중요성을 대신하지 않는다.
   - 각 문단은 독자가 이해해야 할 한 가지를 중심으로 쓴다. 사건의 의미를 설명한 뒤 필요한 수치·비교·출처를 붙이고 앞뒤 문단이 왜 이어지는지 드러낸다. 설명 순서를 모든 문단에 기계적으로 반복하지 않는다. 표·차트가 보여주는 숫자를 본문에서 전부 다시 읽지 말고 핵심 차이와 의미를 설명한다. 문장은 쉬운 말로 쓰고, 낯선 용어는 필요한 맥락에서 짧게 푼다.
   - 확정 원인을 모른다는 이유로 확인된 배경과 출처가 제시한 해석까지 지우지 않는다. 누가 무엇을 우려했는지, 어떤 관측이 이를 지지하거나 제한하는지 연결한다. 한계는 독자의 결론을 바꾸는 지점 가까이에 짧고 구체적으로 쓴다. 전체 해석을 제한하는 자료 부족은 요약에도 밝히고, 특정 문장에만 해당하는 단서는 해당 문장 가까이에 둔다. 같은 주의 문구를 반복하지 않되 반복을 줄이려고 중요한 불확실성을 숨기지 않는다.
   - 제출 전 제목·첫 요약·소제목을 이어 읽고 핵심이 드러나는지 확인한다. 본문에서는 ‘무슨 일이 있었고 왜 중요한가’, ‘어디까지 설명할 수 있는가’, ‘다음에 무엇을 볼 것인가’가 연결되는지 살핀다. 출처가 붙은 문장이라도 의미를 설명하지 못하면 보완하고, 지워도 독자의 이해가 달라지지 않는 반복은 덜어낸다. 분량이나 섹션 수를 채우기 위해 내용을 늘리지 않는다.

**2026년 11월 20일 엔비디아 보도에 적용한 예.** 독자가 “SEC가 조사를 발표해 엔비디아가 하루 14% 내렸고, 그 때문에 나스닥이 5% 하락했다”고 읽게 되는 제목과 요약은 고친다. 당시 새 소식은 앞서 알려진 조사의 초점에 관한 취재였고, SEC는 논평을 거절했다. 다음처럼 쓰면 무엇이 새로 알려졌고 주가가 이미 어디까지 움직였는지 드러난다.

> 엔비디아 주가는 로이터 보도 전부터 전일 종가보다 6% 넘게 하락했다. 로이터는 소식통을 인용해 미 증권거래위원회(SEC)가 회계 문제를 살펴보고 있다고 보도했다. 보도 뒤 한때 주가는 전일 종가 대비 약 13% 낮은 수준에서 거래됐다.

### 무엇을 조사하고 앞에 배치하는가

전 회차의 핵심 변수와 미확보 항목, 공식 경제 일정, 주요 기업 IR 일정, 지수·섹터 움직임을 함께 확인한다. 그중 본문에 넣을 내용은 아래 기준으로 선정한다. 조사 대상과 기사에 반드시 포함할 대상을 동일하게 취급하지 않는다.

| 우선 검토 대상 | 포함·배치 기준 | 제외하거나 짧게 처리할 경우 |
| --- | --- | --- |
| 시장 전반의 가격 변화 | 주요 지수의 방향, 상승·하락의 폭과 확산, 금리 등 관련 지표와의 관계 | 의미 있는 새 해석 없이 같은 숫자를 반복하는 설명 |
| 경제지표·정책·연설 | 금리·성장·물가 기대를 바꿀 발표, 이미 확인된 반응, 발표 시점의 가까움 | 시장 영향 경로를 설명할 수 없는 일정의 전수 나열 |
| 주요 실적·어닝콜 | 지수 비중뿐 아니라 주도 섹터, 공급망, 투자 지출·수요 전망에 미치는 범위 | 개별 기업에 국한된 작은 변화, 근거 없는 관심 순위 |
| 흐름을 바꿀 새 증거 | 기존 핵심 해석을 지지·약화·반박하는 실적, 수요, 투자 지출, 정책 변화 | 하루 등락만으로 중기 추세의 끝이나 재개를 단정하는 설명 |
| 미확인 중요 정보 | 독자가 판단을 보류해야 하는 이유와 확인 예정 자료 | 루머를 주요 사실로 승격하거나 조사 실패를 평온한 날로 표현 |

단순 점수 합산이나 고정된 기업 수를 초기 규칙으로 만들지 않는다. 중요도 판단의 근거는 구조화된 내부 작성 정보에 남기고, 독자에게는 “왜 지금 중요한가”를 자연스럽게 설명한다. 소문·검색량이 큰 것과 시장 영향이 큰 것을 구분한다.

### 항목별 작성 형식

- 사건: **무슨 일이 있었는가 → 확인된 시장 반응 → 연결 근거와 해석의 한계 → 다음 확인점**. 서로 다른 시점의 사건과 가격 반응을 섞지 않는다.
- 예정 이벤트: **예정 시각·출처 → 내용과 간단한 설명 → 주목할 이유 한 문장**. 결과별 시나리오를 길게 늘리지 않고 확인 가능한 컨센서스가 없으면 예상치를 만들지 않는다.
- 어닝콜: 실적 발표와 콜의 시각을 각각 구분한다. 주요 수치의 회계 기간, 단위, GAAP·조정 수치, 가이던스와 실제 실적을 구별한다. 콜 원문을 확보하지 못했다면 실적 보도자료만 읽고 콜 전체를 확인했다고 표현하지 않는다.
- 예정 안내→다음 장후 결과 연결: 같은 사건의 식별자를 유지해 “예고한 확인점 / 발표 결과 / 실제 반응 / 남은 변수”를 연결한다. 이전 안내를 모두 다시 길게 쓰지 않는다. 발표 연기·미발표도 결과 상태로 표시한다.
- 흐름 점검: **기존 해석 → 이번에 추가된 증거 → 유지·약화·변화·판단 유보 → 반대 증거가 될 조건**. 이전 해석이 없으면 새 관찰로 시작한다. 기업 투자 계획 발표를 실제 집행이나 공급업체 매출 확정으로 바꾸지 않는다.

### 출처와 시각자료

- 발표 주체의 원문·기업 IR은 발표 사실, 계약한 데이터 공급원은 가격·시계열, 언론·분석은 해당 출처의 보도·해석으로 구분한다. 출처별로 확인 가능한 범위가 다르며 공식 자료에도 수정이나 지연이 있을 수 있다.
- 상세 본문의 주요 수치와 주장 가까이에 짧은 출처 링크를 둔다. 글 끝의 출처 목록에서 기관·문서명, 발표 시각, 확인 시각을 볼 수 있게 한다. 홈의 짧은 안내와 상세의 근거 표시 역할은 10절을 따른다. 직접 읽지 않은 원문을 읽었다고 표시하지 않는다. 동일 보도의 재전재를 별도 근거로 늘리지 않는다.
- 요약에는 본문의 근거와 연결되는 내용을 쓴다. 외부 자료 전체를 복제하지 않고 필요한 사실·제한된 인용·자체 설명을 제공한다. 출처 표기가 데이터의 공개 이용 권한을 대신하지 않는다. 공급원과 권한은 기술 설계 3절에서 관리한다.
- 제목은 해당 회차의 구체적인 사건·대상·움직임을 앞세운다. 첫 요약은 제목을 반복하는 대신 무엇을 비교하거나 확인하는지 한두 문장으로 설명하고 필요한 불확실성·미확보 상태를 유지한다. “시장의 온도”, “확신” 같은 추상적인 표현만으로 읽을 이유를 대신하지 않는다. 2026-11-01 사용자 요청에 따라 가상 샘플의 제목·첫 요약에 적용했으며, 실제 생성 결과의 품질 검증은 별도로 필요하다.
- 확정된 초기 차트 범위는 지수의 일별 추이와 섹터별 등락 비교 등 시장 전체 흐름 중심이다. 사건 전후의 장중 차트를 필수로 만들지 않는다. 주요 발표의 실제치·확인된 예상치 표도 필요한 경우 사용한다. 해당 회차의 질문을 설명하는 데 필요한 것만 넣으며 데이터 없는 그래프는 생성하지 않는다.
- 지수·ETF·선물은 종류와 이름을 명시한다. 가격 수준이 다른 자산의 추이를 비교할 때는 같은 시작점을 기준으로 정규화하는 등 비교 기준을 설명한다. 정규장 종가와 시간외 가격을 같은 구간의 등락처럼 비교하지 않는다.
- 차트에 대상, 단위, 기간, 기준 시각, 출처와 필요한 지연 안내를 붙인다. 색상 외에 부호·문자·선 모양 등을 사용하고 요약 문장 또는 값 표를 함께 제공한다. 모바일에서도 출처와 핵심 값에 접근할 수 있어야 한다.

### 생성 후 보고서와 근거 대조 — 2026-11-17 사용자 요청

생성한 보고서에 첨부한 자료가 실제 내용을 뒷받침하는지 공개 전에 확인한다. 링크 존재 여부에 더해 종목·지표, 수치·단위·비교 기간, 정규장/시간외, 발표/예정·추정의 구분, 인용 발언과 인과 설명의 강도를 대조한다. 제목과 요약에도 본문보다 강한 주장을 넣지 않는다. AI는 이 검증이 필요하다고 판단했으며 아래 세부 흐름은 구현 방향이다.

사용자는 후속 답변에서 **AI가 보고서와 첨부 근거를 읽고 대조하는 검사**를 뜻한다고 명확히 했다. 의미 대조는 작성과 분리한 AI 검증 호출이 맡고, 기존 기계 검사는 숫자·날짜·구조의 오류를 거르는 보조 역할로 유지한다. 검증 AI에는 보고서만이 아니라 실제로 확인한 출처 내용과 관측 데이터를 함께 제공한다. 근거 부족·충돌·원문 접근 실패는 확인 불가로 남기고 통과로 취급하지 않는다. 잘못된 항목은 기존 제한적 보정 또는 제외·한계 표시 정책을 따르며, 전체 자료가 부족하면 확인 가능한 내용과 미확보 상태를 제공한다. 모델이 재확인했다는 사실만으로 정확성을 보장하거나 검증 신뢰도 점수를 표시하지 않는다. 검증·필요한 추가 검색도 같은 회차 비용에 포함한다.

비공개 시험에서는 준비한 근거 묶음으로 구조 검사와 별도 모델의 원문 대조를 실행했다. 정규 자동 발행으로의 연결은 후속 단계다. [검증 흐름과 적용 범위](TECH_SPEC.md#생성-후-근거-검증의-보완-범위--2026-11-17)

## 10. 화면·디자인 — 초기 기준 채택, 구현 후 조정

### 화면과 이동

사용자는 별도 사전 시안 확정 대신 아래 화면안을 초기 기준으로 채택하고 구현 후 조정하기로 했다. 색상·서체·여백은 공통 스타일로, 요약·목차·차트·출처는 공통 표시 요소로 관리하는 기술안을 적용해 반복 수정을 쉽게 한다. 정보 구조나 데이터 계약까지 바뀌는 수정은 단순 스타일 수정과 작업 범위가 다르다. 수정 시간을 미리 보장하지 않는다.

공개 화면은 홈·지난 글 목록과 브리핑 상세를 중심으로 한다. 관리 화면은 별도 인증 후 접근한다. 불필요한 소개 랜딩페이지를 먼저 통과하게 하지 않는다.

홈의 PC 배치 예시:

```text
NOCT Brief                         지난 브리핑
미국 증시 브리핑                    다음 발행 · {세션·한국 날짜·시각}

최신 {장전 또는 장후} 브리핑 · 미국 {거래일}
[가장 최신 회차의 핵심을 담은 큰 제목]
짧은 요약 한 문단
브리핑 읽기 →       발행 시각

지난 브리핑    미국 거래일 [날짜]    [전체 / 장전 / 장후]
미국 거래일 | 장전 제목 · 한국 발행 시각 · 자료·정정 표시
            | 장후 제목 · 한국 발행 시각 · 자료·정정 표시
이전 회차 더 보기
```

PC·모바일 모두 최신 보고서 하나를 단독 메인으로 배치하고 이전 회차는 아래 기록 목록으로 내려 위계를 분리한다. 장전·장후에 관계없이 공개·검증 완료된 회차 중 대상 발행 시각이 가장 최신인 보고서를 선택한다. 과거 회차의 재발행·정정 시각 때문에 메인이 교체되지는 않는다. 첫 화면에 모든 내용을 억지로 넣기 위해 글자를 줄이지 않는다. 날짜 필터는 **미국 거래일**을 사용하고 한국 발행 시각은 별도로 표시한다. 목록 필터는 메인 보고서에 영향을 주지 않는다.

홈의 주된 역할은 가장 최신 보고서가 무엇을 다루는지 바로 이해하고 읽게 하는 것이다. 메인 카드는 세션·미국 거래일→제목→짧은 요약 한 문단→읽기·발행 시각 순서를 사용한다. 요약 항목을 여러 블록으로 펼치거나 항목별 라벨·출처·주의 문구를 반복하지 않는다. 현재는 발행된 첫 요약의 문장을 그대로 표시하고, 요약이 없으면 요약 없이 발행했음을 안내한다. 한두 문장으로 내용을 안내하는 것을 편집 기준으로 삼되 길이에 맞춰 문장 일부를 자동으로 잘라내지 않는다. 중요한 조건·불확실성은 짧은 문장 자체에서도 유지해야 한다. 화면 단계에서 저장된 문구를 별도로 꾸며 바꾸지 않는다. 후속 사용자 요청에 따라 가상 샘플의 제목·첫 요약을 기존 본문 범위 안에서 구체화했으며, 저장된 로컬 샘플은 이전 버전을 보존하고 수정 이유를 남겼다.

상세에서는 사실·출처 해석·가능한 해석 구분, 각 항목의 근거·한계, 자료 기준 시각을 충분히 제공한다. 홈에는 열기 전에 알아야 할 발행 지연·일부 자료 미반영 상태를 유지하며 가상 데이터 안내는 페이지 상단에 한 번 표시한다. 소개·다음 일정은 짧게 유지하고 최신 보고서보다 크게 강조하지 않는다. 홈 단순화 이후 사용자가 “가장 최신 보고서 말고는 나머진 참고용”이라고 명시해 단독 메인으로 조정했다. 구체적인 폭·서체·간격은 이 우선순위를 구현하기 위한 AI 선택이며 사용자 최종 미감 승인과 구분한다.

후속 다듬기에서는 소개·샘플 안내·메인 사이의 여백을 줄이고 다음 발행 라벨을 시각 정보 옆에 둬 메인까지의 높이를 압축했다. 좁은 화면은 자연스럽게 줄바꿈하며 일정·자료 안내 글자를 더 작게 만들지 않는다. 가상 데이터 문구는 실제 시황이 아님을 유지하면서 짧게 다듬는다. 단독 메인 구조·색상·주요 글자 크기·기록 목록은 유지한다.

지난 글은 메인 회차를 제외한 뒤 미국 거래일 내림차순으로 묶고 같은 날은 장전→장후 순서로 읽는다. 같은 거래일의 다른 회차는 남기고, 남은 공개 회차가 있는 6개 거래일을 한 페이지로 삼아 두 세션이 페이지 경계에서 나뉘지 않게 한다. 최신 회차 제외와 날짜·세션 필터를 적용한 공개 결과를 기준으로 묶으며, 없는 회차를 가짜 항목으로 채우지 않는다. 최신 회차만 해당하는 필터는 빈 목록을 표시하되 메인은 유지한다. 빈 상태는 지난 브리핑이 없음을 안내해 공개된 메인 보고서까지 없는 것으로 오해하지 않게 한다. 필터 적용 버튼은 보조 행동으로 표현한다. 기존 장전 기록을 보존하는 아카이브 배치이며, 새 발행은 2026-11-24에 정한 장후 하루 한 편을 따른다.

### 지속 적용할 디자인 원칙 — 사용자 확정

2026-11-01 사용자는 디자인 공식을 기준으로 수정하고, 이후에도 큰 틀은 유지하면서 세부만 조정하도록 요청했다. 아래 원칙을 새 화면과 후속 수정에 계속 적용한다. 원칙의 채택과 개별 색상·크기·효과에 대한 최종 디자인 승인은 구분한다.

- **배분:** 60–30–10을 색상 배분의 출발점으로 삼는다. 블랙 계열의 지배적인 배경, 이를 받치는 차콜 표면, 제한된 유채색 강조의 순서를 유지한다. 이는 화면 픽셀을 정확히 60/30/10으로 채우는 규격이 아니다. 긴 읽기 화면에서 강조색을 10% 채우려고 장식을 늘리지 않는다. [NN/g 색상 활용 지침](https://www.nngroup.com/articles/color-enhance-design/)
- **역할:** 색상은 공통 의미별 변수로 관리한다. 블루바이올렛은 주요 행동·링크·선택·포커스, 앰버는 가상 데이터·자료 한계·오류 안내, 중성색은 일반 정보와 구조, 차트 색은 데이터 표현에 사용한다. 같은 색을 무관한 장식과 상태에 반복 배정하지 않는다. [Material 색상 역할](https://m3.material.io/styles/color/roles)의 역할·표면·글자색 짝 원칙을 참고하며 전체 Material UI를 도입하는 것은 아니다.
- **가독성:** 일반 텍스트는 최소 4.5:1, 큰 텍스트와 식별에 필요한 조작 경계·그래픽은 최소 3:1을 확인한다. 그라디언트는 글자가 놓이는 가장 불리한 배경까지 계산한다. 작은 글자는 가능한 여유 있는 대비를 확보하고, 낮은 대비 자체를 고급스러움으로 해석하지 않는다. [WCAG 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- **정보 구분:** 색만으로 의미를 전달하지 않는다. 주의 문구, 상승·하락 부호, 링크의 밑줄 또는 명확한 조작 형태, 선택 값과 키보드 포커스를 함께 제공한다. 제목→요약→본문→보조 정보의 크기·굵기·간격 위계와 정렬을 유지한다. [WCAG 색상 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- **조정·확인:** 실제 콘텐츠와 PC·모바일 화면에서 읽기 흐름과 조작 상태를 확인한다. 여백·색조·크기·그라디언트 강도의 작은 조정은 허용하되 위 배분·의미·가독성 기준 안에서 선택하고 중요한 변경 이유와 검증 결과를 남긴다. 수치 통과를 체감 가독성이나 최종 미감의 승인으로 대신하지 않는다.
- **브라우저 기능의 도입 기준:** 2026-11-26 사용자 지시에 따라 새로 채택하는 CSS·브라우저 기능은 지원 대상 주요 브라우저의 Stable 버전에 포함된 시점부터 최소 1년이 지나야 한다. 표준 문서 공개일, 베타·개발자 미리보기 지원일을 기준으로 삼지 않는다. 기능 안에서도 실제 사용하는 문법의 지원 시점을 확인한다.

## 12. 제품 완료 기준과 검토할 선택

### 완료 기준 제안

1. 미국 거래일, 서머타임, 주말·휴장·조기 폐장 정책에 맞춰 회차와 다음 예정 안내가 일치한다. PC가 꺼진 상태에서도 원격 실행되는지 실제 확인한다.
2. 대표 네 상황(평온한 날, 중요 발표 전, 주요 콜 중심, 자료 지연)의 샘플에서 요약 우선·가변 배치·시각 구분·자료 한계가 유지된다. 주요 수치·사실은 추적 가능한 근거와 연결되고 확인할 수 없는 항목은 제외 또는 표시된다. 이것만으로 모든 인과 해석이 참이라고 보장하지 않는다.
3. 장후 결과와 다음 거래일까지의 예정 이벤트를 구분해 읽을 수 있고, 정정은 원래 자료 시점과 구분된다. 실패 재시도와 비공개 전환이 기존 공개 글을 잘못 덮어쓰거나 노출하지 않는다.
4. PC와 모바일에서 홈 → 상세 → 출처 → 지난 회차의 흐름, 필터, 긴 본문·표·차트, 로딩·빈 화면·실패 상태를 직접 확인한다. 2·10절의 가독성 기준을 점검한다.
5. 사용자 결정: 별도의 공개 전 운영 시험 기간이나 5개 거래일의 비공개 관찰을 공개 조건으로 두지 않는다. 개발 도중 실제 내용·화면을 보며 수정하고 공개한 뒤에도 보완한다. 개발 중 빌드·핵심 기능·권한·비밀정보·시각 처리 확인과 매회 자동 콘텐츠 검사는 유지하며, 이를 별도의 장기 비공개 검증 절차로 늘리지 않는다. 현재의 개발 승인 절차는 유지한다.
6. 자동 발행에 연결하기 전에 장후 결과와 예정 안내를 합친 실제 리포트의 품질을 먼저 완성한다(2026-11-22 방향을 2026-11-24 구성에 맞춰 갱신). 사용자가 읽고 시장 움직임의 배경·다음 주요 변수·설명의 한계를 파악할 수 있는지 평가한다. 영상을 다시 찾아본 이유가 빠진 핵심 정보인지 개인적 추가 관심인지 구별해 개선한다. 측정하지 않은 시간 절감률을 성과로 쓰지 않는다.

2026-10-27 사용자 구현 지시에 따라 공개 화면과 가상 네 상황, PostgreSQL 발행·정정·작업 처리, 권한·시간·콘텐츠 검사, 운영 준비 코드를 구현했다. PC·모바일 화면과 로컬 기능을 확인한 결과는 기술 설계 12절에 둔다. 실제 시황 자동 수집·유료 모델 품질·원격 자동 발행·계정 연결·운영 복구는 미완료이며 제품 전체 완료로 선언하지 않는다. 기존 제품 범위와 발행 정책은 변경하지 않았다.
