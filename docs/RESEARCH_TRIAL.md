# 자료수집 비교 시험

2026-11-26 사용자는 자료수집 모델·추론 강도를 생성·검증과 독립된 환경 변수로 설정하고, GPT-6.2 Sol과 GPT-6 Astra의 high·xhigh 네 조합을 시험하도록 지시했다. 이번 범위는 비공개 자료수집과 Codex의 근거 평가다. 새 보고서 작성, 정규 자동 수집·발행 연결, 운영 모델 확정, 외부 계정 변경·배포·커밋·푸시는 포함하지 않는다.

## 공통 조건

- 첫 대상은 앞선 보고서 시험과 같은 미국 거래일 2026-11-20이다. 제품 명세에서 정한 시장 전체 중심 장후 결과와 다음 실제 거래일 장중까지의 예정 이벤트에 필요한 자료를 수집한다.
- 자료 마감은 2026-11-21 09:30 KST (2026-11-20 19:30 EST), 다음 거래일 폐장은 2026-11-24 06:00 KST (2026-11-23 16:00 EST)다. 코드가 거래 달력과 날짜별 시간대로 계산한다.
- 같은 프롬프트·출력 계약·도구·출력/도구 상한을 사용한다. 모델과 추론 강도만 다르다. 이전 Codex 원고·근거 묶음, 사건 목록, 다른 후보의 결과는 입력하지 않는다. 기존의 기본 공급원은 시작점이며 탐색을 해당 사이트로 제한하지 않는다.
- 각 조합은 한 번 실행한다. search → 원문 열람 → 부족하거나 충돌하는 근거 확인 → 후속 조사를 모델이 수행한다. 재작성·보정·자동 재제출은 하지 않는다. 기존 응답 ID 조회는 새 요청이 아니다.
- 기본 실행은 비용 예약이 큰 조합부터 순차 진행한다. 한 조합이 오래 처리 중이면 공통 원장의 예약 합계가 한도 안에 드는 독립 조합을 병행할 수 있다. 프롬프트·도구·토큰 조건은 바꾸지 않으며 실행 순서·겹친 구간을 비용과 지연 해석에 남긴다.
- 초기 비교 상한은 추론과 최종 출력을 합한 32,000토큰, 내장 도구 총 40회다. 검색 문맥은 medium, 반환 토큰 예산은 기본값이다. 이는 품질이 검증된 최적값이나 목표 분량이 아니다. search/open_page/find_in_page는 활동을 구분하고 검색어·URL 수와 혼동하지 않는다. 상한에 도달한 후보는 제한 조건을 함께 평가한다.
- 검색 색인과 외부 페이지는 실행 중 달라질 수 있다. 같은 날의 한 번씩 시험은 네 조합의 현 사례 비교이며 반복 안정성이나 모든 거래일의 우열을 입증하지 않는다.

## 입력·출력과 원문 시점

실행 프롬프트와 JSON 계약은 `lib/research-trial.ts`가 관리한다. 출력은 출처, 수치·사실·출처의 해석, 예정 이벤트, 조사 범위와 미해결 사항을 연결한 연구용 자료다. 발행용 Bundle로 자동 승인하지 않는다.

기사·페이지의 게시일, 수정판 공개 시각, 관측 시각, 사건 발생 시각, 조사 기간, 예정 시각을 구분한다. 날짜만 있는 근거에 시·분을 만들어 넣지 않는다. 자료 마감 뒤 검색한 페이지는 당시 인용 내용의 판본이 이미 공개됐음을 입증해야 한다. 현재 일정이나 사후 발표 결과로 예정 정보를 소급하지 않는다. 원문을 직접 읽은 근거와 검색 요약만 확인한 후보를 구분한다.

자동 검사는 형식·연결·시각 경계를 점검한다. 링크가 존재하거나 모델이 `confirmed_as_of`라고 썼다는 이유만으로 내용이 검증됐다고 판단하지 않는다. 원문과 도구 활동, 출처 메타데이터, 실패·중단 정보도 보존한다.

## 평가 기준

기존 Codex 조사와의 일치율을 점수로 삼지 않는다. 기존 편집본은 여러 차례 조정한 잠정 참고 자료이며 정답이나 수집 범위의 상한이 아니다. 네 결과의 합집합도 정답이 아니다.

| 기준 | 확인할 내용 |
| --- | --- |
| 필요 정보의 충족 | 시장 대표 지수와 비교 기준, 확산·업종 차이, 시장을 이해하는 주요 재료, 확인된 장후 변화, 중요한 예정 이벤트가 충분한가 |
| 근거의 정확성 | 원문이 실제 주장·숫자·대상·단위·조건을 뒷받침하는가. 취재 해석과 사실이 구별되는가 |
| 시점의 적합성 | 해당 판본과 내용이 마감 전에 알려졌는가. 정규장·장후·예정·사후 결과를 섞지 않았는가 |
| 조사 판단 | 설명을 바꾸는 반대 정황과 모순을 확인했는가. 중요도가 낮은 자료만 늘리지 않았는가 |
| 미확인 범위의 정직성 | 접근 실패·미확보·불명확한 시각을 구분하고 추측으로 채우지 않았는가 |
| 운영 효율 | 실제 비용·시간·도구 활동·토큰, 미완성 여부와 한도 도달을 함께 볼 때 사용할 가치가 있는가 |

가능한 범위에서 모델명·강도·비용을 숨긴 후보 A~D를 먼저 읽고 판단 근거를 남긴다. 네 결과가 모두 놓친 중요한 자료가 있는지 공식 발표·일정과 별도의 시장 대조 자료를 확인한다. 새로운 유효한 자료는 어느 후보가 찾았든 인정한다. 기사 수, 출처 수, 새로움 자체는 품질 점수가 아니다.

필요 정보별로 충족·부분 충족·미충족·검증 불가를 구분한다. 중요한 오류, 추가 유효 근거, 공통 누락, 원문 접근 제약을 별도로 설명하며 점수 하나로 덮지 않는다. 내용 검토 뒤 모델별 비용과 시간을 공개해 채택·후속 시험을 제안한다.

## 실행과 비용

`npm run research:trial -- 2026-11-20 --matrix`는 네 요청과 눈가림 후보 매핑을 `.local/trial-research/` 아래 저장한다. API·DB 호출 없는 사전 검사다. 같은 명령에 `--run`을 붙이면 승인된 네 조합을 차례로 실행한다. `--matrix`가 없으면 수집 환경 변수의 모델·강도를 사용한다. 설정이 달라진 요청으로 이전 결과를 덮어쓰지 않는다.

수집 전용 변수는 `OPENAI_RESEARCH_MODEL`, `OPENAI_RESEARCH_REASONING_EFFORT`, `OPENAI_RESEARCH_MAX_OUTPUT_TOKENS`, `OPENAI_RESEARCH_MAX_TOOL_CALLS`다. 생성·검증의 모델·상한과 독립이다. 기본 Sol 6.2·high는 시험 출발값이며 운영 채택 결과가 아니다.

기존 비공개 시험 DB의 같은 비용 원장과 잠금을 사용하며 `research` 단계를 추가한다. 같은 회차 $10·KST 하루 $30·시험 전체 $100 한도에 기존 보고서 시험까지 합산한다. 비용 예약에는 웹 문맥 128k토큰 여유분·요청 크기·출력 상한·도구 호출을 반영한다. 웹 반환량은 정확한 숫자로 제한할 수 없어 예약액은 추정이고 공급자가 보장하는 청구 상한이 아니다. 실제 토큰 사용량과 search action 수로 정산하고, 비용 불명확·접수 불명 상태는 예약액을 유지한다. 일반 입력·캐시·출력·장문 배수를 반영하며 검색 내용 토큰을 중복 계산하지 않는다. 표시 비용은 API 사용량과 공개 요금의 환산이며 청구서 대조액과 구분한다.

검색 도구와 모델 조합은 실제 네 요청으로 확인했다. 세 건은 완성됐고 Sol xhigh는 출력 상한으로 중단돼 원응답과 부분 내용을 보존했다. 내용 평가·비용·검증 결과는 TECH_SPEC 8·12절을 따른다. 미완성·실패도 비교 결과이며 유료 재시험은 별도 결정한다.

검색 비용은 응답의 `tool_usage.web_search.num_requests`가 있으면 그 공식 청구 대상 집계를 우선하고, 없으면 search action 수로 추정한다. 도구를 반복 사용한 응답의 합산 입력이 272k를 넘을 때 이를 장문 요금 판정에 그대로 써도 되는지는 공개 문서만으로 확인하지 못했다. 그 경우 원장에는 장문 배수 가정을 보수적으로 적용하고 결과에는 기본 요율 환산액도 함께 남긴다. 실제 청구 요율은 별도 비용 내역 대조가 필요하다. 처리 중의 빈 output·usage는 도구를 사용하지 않았거나 무료라는 뜻이 아니다.

2026-11-26 후속 사용자 승인으로 **2026-11-20 장후 회차만 $15**로 조정했다. 다른 회차 $10, 하루 $30, 전체 $100은 유지한다. Astra xhigh 실측이 초기 예약 추정보다 커서 마지막 Astra high가 기존 한도에 차단된 뒤 받은 승인이다. 같은 회차·같은 수집 모델의 완료된 비용이 있으면 새 예약액은 초기 추정과 그 실측 중 큰 값을 사용한다. 이는 추가 요청의 승인 검사 기준이며 최종 청구액 보장이 아니다.
