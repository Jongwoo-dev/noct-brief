## 착수 판단과 남은 준비

2026-10-27 사용자가 명시적으로 구현을 지시했고 독립적으로 가능한 화면·DB·처리·검증·운영 준비 코드를 구현했다. 실제 결과는 TECH_SPEC 12절, 구체적인 외부 선택·추천은 INTEGRATION_READINESS.md, 운영 절차는 OPERATIONS.md를 따른다. 초기 AI 검토 판단: 문서만으로 구현을 시작할 범위·구조·검증 기준이 갖춰졌다. 큰 제품 선택을 처음부터 다시 묻지 않고, 새 대화에서 문서를 읽은 뒤 사용자의 명시적 구현 지시에 따라 진행한다. 모델 변경이나 별도의 승인 문구 반복은 필요하지 않다. 아래 준비를 모두 마쳐야 화면 개발을 시작할 수 있다는 뜻은 아니다. 실제 연동·공개에 필요한 사항은 해당 작업 전에 해결한다.

| 필요한 시점 | 준비할 내용 | 구체적인 범위 |
| --- | --- | --- |
| 구현 시작 전 | 기준 문서 읽기와 명시적 구현 지시 | 사용자 확정 사항과 AI 세부안을 구분. 이 기준을 정리·커밋한 대화의 승인은 문서 작업에 한정 |
| 승인 후 초기 구현 | 정식 프로젝트 구성·버전 확인, 샘플 기반 화면·DB·발행 흐름 | 기존 Next.js·TypeScript·Node.js·PostgreSQL 기준. 패키지 호환성·세부 파일 배치는 구현 과정에서 확인 |
| 실제 데이터 연동 전 | 시장 데이터 공급원·공개 이용권·가격·지연 범위 | 시세·차트·기업 자료의 실제 확보 및 공개 조건 확인. 중요한 비용·범위 변경은 사용자와 결정 |
| 실제 AI 연동 전 | 운영 모델·도구 조합·계정 한도·비용 | 모델은 교체 가능한 생성 경계와 설정으로 분리. 승인된 시험에서 품질·사용량·지연 확인 |
| 기능 연동·배포 준비 | Google OAuth·텔레그램·API 키, AWS·도메인·HTTPS·예약 실행 | 키는 샘플이 아닌 비밀 저장 수단에 등록. 구매·계정 변경·외부 공개는 기존 승인 범위 준수 |
| 배포 준비 | 백업 저장소·실행 시각·복구 절차 | 하루 1회·14일 보관은 확정. 서버 밖에 보관하고 새 서버 재구성·DB 복원을 확인 |

현재 가장 큰 외부 의존성은 **실제 시장 데이터의 확보 범위·공개 이용 조건·비용**이다. 샘플 화면이 완성됐다고 이를 해결한 것으로 취급하지 않는다. 실제 수집·생성 단계에서는 기존 공급원 조사와 시험 한도를 기준으로 준비한다. 현재 순서는 기술 설계 10절을 따른다.

관련 근거와 구현 순서는 [기술 설계](TECH_SPEC.md) 3·5·6·9·10절을 따른다. 외부 설정이 없더라도 독립적으로 가능한 화면·저장·작업 처리·검증·운영 스크립트 작성을 계속한다. 실제 외부 호출이 필요한 부분과 모의 검증만 끝난 부분을 구분해 보고한다. 콘텐츠 편집 세부안·화면 값은 실제 샘플과 동작을 보며 조정하되, 미확정 제안을 사용자 확정으로 바꾸지 않는다.

비용 수치와 산식은 **기술 설계 8절 한곳**에서 관리한다. 도메인·복구 저장·AI·시장 데이터·세금·초과 사용량의 포함 여부를 함께 확인한다. 예시 금액은 실측 청구액이나 상한이 아니며, 서비스 도입 직전에 조건과 가격을 다시 확인한다.

## 수정하는 방식

1. 검토할 항목 하나를 고르고 사용자 결정과 AI 제안을 구분한다.
2. 결정은 제품 요구사항이면 제품 기획에, 기술·운영 사항이면 기술 설계에 반영한다. 이 목록에는 상태와 다음 항목만 갱신한다.
3. 관련 문서의 표현·전제·링크를 함께 확인한다. 미확정 사항은 그대로 남기고 실제로 검증한 결과만 검증 완료로 표시한다.

기존 구현·배포 승인 기준은 AGENTS를 그대로 따른다. 문서 정리나 검토 항목의 완료는 구현 승인을 뜻하지 않는다. 화면 세부 조정과 개발 중 검증은 해당 명세의 계획을 따르며, 이 목록 때문에 별도의 장기 비공개 시험이나 추가 승인 단계를 만들지 않는다.
